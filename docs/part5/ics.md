# 工控与 OT 场景的国密化

工控（OT）是国密改造中**约束最苛刻**的领域：协议多为上世纪设计（无安全层）、设备寿命 15~20 年、控制回路对延迟抖动零容忍、"可用性优先于机密性"的行业铁律。本章给出可落地的改造路线与判断框架。

## 1. OT 与 IT 的差异：改造约束从哪来

| 维度 | IT（办公/互联网） | OT（工业控制） |
| --- | --- | --- |
| 可用性语义 | 服务降级可接受 | **停机=生产事故**，安全仪表中断可能导致物理危害 |
| 实时性 | 无硬性要求 | 控制回路毫秒级，密码运算延迟要计入抖动预算 |
| 设备形态 | 可随时升级 | **哑终端**（无操作系统/无算力/无升级通道）占比高 |
| 设备寿命 | 3~5 年 | 15~20 年，存量协议无法靠"换设备"解决 |
| 补丁策略 | 定期更新 | 停机窗口稀缺，验证周期长 |
| 网络边界 | 扁平化 | **分区+纵深**（安全域边界是天然的密码部署点） |

结论先行：OT 的国密化几乎从不在"改协议栈"下手，而在**边界与网关**做密码加固——这是本章两条主线路的由来。

## 2. 主流工控协议的安全能力现状

| 协议 | 内建安全 | 国密化可行路径 |
| --- | --- | --- |
| **Modbus TCP/RTU** | 无（1980 年代协议，全明文） | 只能网关封装/隧道 |
| **IEC 60870-5-104** | 无（电力远动主流协议） | 纵向加密装置（电力标准做法，见第 5 节） |
| **OPC UA**（IEC 62541） | **有**：SecurityPolicy 体系（证书 + 通道签名/加密） | 见第 3 节——标准套件族无 SM 算法，是国内改造的焦点 |
| DNP3 | 有 SA 版本（国际电力） | 网关封装为主 |
| PROFINET/EtherCAT | 早期无，新版本在补 | 网关封装 |
| MQTT | TLS（国际算法） | TLCP/DTLCP 替换或网关 |

一个重要的行业事实：**OPC UA 的 SecurityPolicy 家族（None / Basic256Sha256 / Aes128_Sha256_RsaOaep / Aes256_Sha256_RsaPss / PubSub-AesCTR…）由 OPC Foundation 统一定义，目前不含 SM 算法套件**——OPC UA 规范虽然允许实现者"以少量代码改动扩展新算法"，但自定义 `SM-SecurityPolicy` URI 意味着与所有标准客户端互操作断裂，实际上只存在于个别厂商的私有生态里。

## 3. OPC UA：协议内嵌 vs 网关封装的路线抉择

```text
路线 A：协议内封装（自定义 SM SecurityPolicy）
  在 OPC UA 栈里注册 SM2/SM3/SM4 算法套件（证书 SM2、通道密钥 SM4-GCM、
  MAC HMAC-SM3），SecurityPolicy URI 自定义
  ✔ 端到端安全，会话/审计与应用层安全策略（用户令牌、RBAC）天然联动
  ✘ 互操作断裂（只对接同栈客户端）；需改动并维护协议栈；
    OPC UA 1.05 引入 ECC/ECDH 通道（PFS），私改版要持续追赶上游演进

路线 B：网关隧道封装（主流）
  明文 OPC UA/Modbus/104 流量 → 国密网关 → TLCP/IPSec 国密隧道 → 对端网关解包
  ✔ 协议栈零改动、哑设备同样覆盖（设备侧只需网络可达）、批量纳管
  ✘ 端点认证弱化到"网关对网关"；网关内部是明文，网关自身成为高价值目标
```

工程判断（多数场景的答案）：**B 为主、A 为补充**——生产网与管理网的边界、厂站到调度的链路用网关隧道；网关之间的东西向流量里若有高价值控制指令，再对个别链路做 A（两端都是可控的国产 OPC UA 栈时才可行）。选 B 时网关必须按密码产品对待（持证、密钥不出设备、自身过等保密评）。

## 4. 网关封装的产品形态

- **安全接入网关**：TLCP/IPSec 隧道型（对应 GM/T 0022/0024/0026 体系产品），部署在控制网边界，做协议透传 + 隧道加密 + 设备认证；
- **边缘加密网关**（物联网/工业互联网常见形态）：采集侧（Modbus/OPC UA/IEC 104/MQTT 多协议接入）+ 边缘计算 + 国密加密（SM2+SM3 或 SM4+SM3 组合）+ 上行 TLCP/IPSec——本质是"协议网关 × 密码网关"合体，适合多网点数据汇聚场景；
- **纵向加密认证装置**：电力行业的专有形态（见下节），在厂站与调度主站之间做国密隧道 + 认证。

## 5. 电力行业：OT 国密化的样板工程

电力是国内**最早完成 OT 国密体系化**的行业（也是工控密评经验最丰富的样本），其架构被多个行业借鉴：

```text
生产控制大区（安全区 I/II）          管理信息大区（安全区 III/IV）
  ├── EMS/SCADA/远动（104 报文）        ├── MIS/办公/互联网出口
  │        │                                    │
  │        ▼                                    ▼
  │   【纵向加密认证装置】                 【国密防火墙/VPN 网关】
  │        SM2 认证 + SM4 加密隧道              TLCP/IPSec
  │        （厂站 ↔ 调度主站，双向身份鉴别）        （对互联网/第三方）
  │
  └── 横向边界：正/反向隔离装置（物理级隔离，替代密码手段的特例）

终端侧：电表/终端内嵌 ESAM 安全模块（芯片内 SM4 加密 + SM3 校验）
```

要点：**纵向加密装置是"网络边界"的国密化，ESAM 是"终端"的国密化**——边界+终端两件套覆盖了 OT 的两个可控锚点；中间的哑终端与实时协议本体（104 明文报文）不动。这套"边界加密 + 终端安全模块 + 分区分域"的模式适用于绝大多数流程工业。

## 6. 5G + 工业互联网的新变量

- 5G 专网（UPF 下沉）让"无线 last-mile 进控制网"成为可能，空口安全由 NEA/NIA 族承载——注意 **128-NEA3/NIA3（ZUC）在 5G 是可选件**（见 ZUC 章），跨国设备采购与漫游场景要在能力协商里显式确认；
- 5G 用户面完整性保护（UP IP）对控制类业务有价值（4G 所没有的能力）；
- 边缘计算节点（MEC）与控制网之间仍要按 OT 边界处理——5G 只是换了接入方式，**边界密码加固的责任没有转移**。

## 7. 密评视角的工控要点

1. **"不适用"的判定边界**：哑终端（无操作系统、无密码运算能力）对应的测评单元可判"不适用"，但**边界与链路层面必须给出替代性保护**（纵向加密/隔离装置），完全不设防不能靠"设备哑"豁免；
2. 控制网内的**实时性约束**可以作为"部分符合"的整改说明依据，但整改方向仍是边界加固而非给 PLC 加密码；
3. 工控系统定级常为等保三级（关键行业），密评范围按"网络和通信+设备和计算"两层重点展开；
4. 网关/装置/ESAM 全部按**密码产品**核验认证证书（型号、等级与部署环境匹配）。

## 8. 要点速查

| 问题 | 判断 |
| --- | --- |
| 老协议（Modbus/104）能改协议本身吗 | 不能（无安全层设计），一律边界/网关封装 |
| OPC UA 要不要自定义 SM 套件 | 仅两端都是可控自研栈时；跨厂商互联选网关隧道 |
| 实时回路里能加对称加密吗 | 评估抖动预算：SM4 软件加密通常可忽略，公钥运算放握手期/边界 |
| 哑终端怎么覆盖 | 终端侧 ESAM 类安全模块，或接受"边界保护 + 不适用说明" |
| 网关内部明文暴露怎么解释 | 网关按密码产品部署在受控物理/网络环境内，密钥不出设备——密评材料里写清边界论证 |
