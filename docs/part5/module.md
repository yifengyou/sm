# 密码模块与产品认证

算法标准只回答"运算是否正确"；真实系统里部署的是**密码模块**——算法实现 + 一整套防护外壳（接口控制、密钥保护、自测试、物理与侧信道防护）。模块是"算法 → 模块 → 产品 → 系统"合规链条的中间环节，也是密评现场"密码产品必须持证"的判定对象。本章依据 **GB/T 37092-2018《信息安全技术 密码模块安全技术要求》**（行标版 GM/T 0028-2014，修改采用 ISO/IEC 19790:2012）展开。

## 1. 三个层次：算法、模块、产品

| 层次 | 回答的问题 | 规范依据 |
| --- | --- | --- |
| 算法 | 运算正确、数学上安全 | GB/T 32905/32907/32918/38635 等 |
| **密码模块** | 算法实现的外壳是否安全（密钥、接口、自测试、物理防护、侧信道缓解） | **GB/T 37092-2018** / GM/T 0028-2014 |
| 密码产品 | 模块 + 具体形态与用途（密码卡、密码机、VPN 网关、UKey…） | 各产品技术规范 + **商用密码产品认证目录** |

配套检测依据：**GM/T 0039-2015《密码模块安全检测要求》**（国际对照 ISO/IEC 24759）。美国 FIPS 140-3 同样直接采用 ISO/IEC 19790——中美欧密码模块体系在"同一张考卷"上，国密版叠加了国密算法的检测项。

## 2. GB/T 37092 的十一个安全域

| 安全域 | 管什么 |
| --- | --- |
| 规范文件 | 模块边界、接口、安全策略的成文描述——送检时"模块划到哪"由此定 |
| 端口与接口 | 数据/控制/状态接口的分离，旁路路径（bypass）的防护 |
| 角色、服务与操作者 | 谁能做什么（用户/密码官/维修员），高等级要求基于鉴别授权 |
| 软件/固件完整性 | 高等级下用签名/HMAC 校验加载代码，防止固件被替换 |
| 运行环境 | 对 OS/运行时的要求（不可修改性、隔离） |
| 物理安全 | 防拆证据/防拆防护/侵入检测与响应，环境失效测试（EFT/EFP） |
| **非侵入式攻击缓解** | 侧信道（时序/缓存/功耗/电磁）的缓解与测试——国密模块的重点考区 |
| 敏感安全参数管理 | 密钥的生成/建立/输入输出/**零化**（zeroization）全流程 |
| **自测试** | 上电/条件/周期自测试（见第 4 节） |
| 生命周期保障 | 配置管理、交付与运行、开发过程 |
| 其他攻击对抗 | 故障注入等模块声明并缓解的其他攻击类 |

每个域的要求按等级一至四级递进。

## 3. 四个安全等级

| 等级 | 物理安全 | 典型形态 | 典型场景 |
| --- | --- | --- | --- |
| 一级 | 无物理安全要求 | 纯软件模块可行 | 测试工具、应用内嵌加密库 |
| 二级 | **防篡改证据**（拆过必留痕）+ 角色鉴别 | 软件/固件模块主流认证档 | 应用加密中间件、移动端 SDK |
| 三级 | **防篡改防护与响应**（检测到侵入即零化密钥）、环境失效测试 | USB-Key、PCI-E 密码卡、服务器密码机主力档 | 业务系统密码基础设施 |
| 四级 | **侵入检测与响应**贯穿封装全表面、更宽环境范围 | 高等级硬件模块 | KMC 主密钥、CA 根密钥保护 |

要点：

- **软件模块可以认证，但实践中集中在一、二级**——三级的物理防护与自测试要求基本把形态推向硬件；"上不去等级"多数是模块边界划法（把整个 App 当模块）导致的，不是软件天然不行；
- 硬件模块分**单芯片嵌入式 / 多芯片嵌入式 / 多芯片独立**三类，检测的物理攻击面与成本随封装复杂度上升；
- 检测/认证的是**模块单元**，产品（如整机密码机）里往往包含多个已认证模块——采购时看清证书覆盖的是哪一层。

## 4. 自测试：模块的"开机体检"

| 类型 | 时机 | 内容 |
| --- | --- | --- |
| 上电自测试 | 每次加电/复位 | KAT（SM3 "abc"、SM4 单分组、SM2 已知签名对等）+ 固件完整性 + 随机数检测，失败即进入错误状态、拒绝一切服务 |
| 条件自测试 | 触发式 | 随机数连续性、固件/软件加载前校验、旁路操作检查 |
| 周期自测试 | 运行中按周期 | 长时间运行的健康监测 |

与随机数章的 GM/T 0062 四阶段检测（出厂/上电/周期/单次）对齐：模块自测试把"检测要求"固化成产品行为，密评现场靠日志与现场演示核查。**应用侧接密码设备时，确认上电自检证据可导出**是验收动作之一。

## 5. 侧信道与攻击缓解：国密算法的"物理考卷"

### 5.1 攻击面全景

| 攻击类 | 手段 | 针对国密算法的已知面 |
| --- | --- | --- |
| 时序侧信道 | 测量执行时间 | SM2 标量乘非常数时间（窗口/分支依赖秘密）、SM4 查表实现 |
| 缓存侧信道 | 同核探测 cache line | SM4 的 T 表查找、SM2 预计算表访问模式 |
| 功耗/电磁（DPA/SPA/DEMA） | 示波器/近场探头 | SM4 首末轮 S 盒输出、SM2 点乘中间值 |
| 故障注入 | 电压/时钟毛刺、激光、电磁脉冲 | SM2 签名中注入错误点 → 私钥恢复方程；SM4 轮计数故障 |
| 侵入式攻击 | 开盖、FIB 探针 | 直读存储的密钥——等级四的对手模型 |

### 5.2 防护技术清单

- **恒定时间**：Montgomery ladder、无分支逻辑、查表合并/bitslicing（SM4 章已展开）；
- **掩码（masking）与隐藏（hiding）**：中间值随机化、运算时间/功耗抖动，DPA 通用对策；
- **坐标随机化**：SM2 点乘前随机化射影坐标，废掉功耗轨迹的可对齐性；
- **点校验**：验签/解密前检查点在曲线上且阶为 n——同时挡住无效曲线攻击与多数故障注入；
- **冗余与验算**：签名后对结果自验（重算 r）、关键路径双算比对；
- **物理层**：传感器网格、主动屏蔽层（等级四模块的标配）。

### 5.3 检测与验收

- **ISO/IEC 17825**（非侵入式攻击的测试方法学）与 **TVLA**（固定 vs 随机输入轨迹的 t 检验）是泄漏评估的通行做法；等级三/四的模块必须提交非侵入缓解的文档化与测试证据；
- 采购方验收动作：索取检测报告，核对报告覆盖的**算法 × 攻击类 × 等级**矩阵是否包含你要用的高价值路径（例如"SM2 签名 + 功耗分析"）；
- 自研模块送检前先做内部初筛：ChipWhisperer 类开源平台跑一轮 TVLA，比检测机构退回来重改便宜得多。

## 6. 认证流程与证书管理

```text
厂商 ──► 认证申请（市场监管总局/国密局指定的认证机构）
      ──► 资料审查（模块边界、安全策略、规范文件）
      ──► 委托认可实验室型式试验（GM/T 0039 + 产品规范 + GM/T 0062 随机数等）
      ──► 认证决定 ──► 发证（商用密码产品认证证书，官网可查）
      ──► 获证后监督（变更申报；重大变更重新认证）
```

- **证书四要素**：算法、模块形态、安全等级、**型号与版本**——采购核验时四个字段都要与实际部署对上（拿 B 型号的证书配 A 型号设备，是密评现场的高频瑕疵）；
- 列入认证目录的产品，**未经认证不得出厂、销售、进口**（国产与进口同规则）；
- 目录动态扩容：云密码机、密码中间件等新形态陆续纳入，做方案前查最新目录。

## 7. 等级选型：场景速查

| 场景 | 建议模块等级 |
| --- | --- |
| 应用内嵌加密（业务层数据保护） | 一~二级软件模块 |
| 移动端 SDK / 协同签名客户端件 | 二级 |
| 服务器密码卡 / 密码机（业务系统） | 二~三级 |
| USB-Key / 个人私钥载体 | 二~三级 |
| CA/KMC 根密钥、签名服务器 | 三级及以上（多数选四级） |

与 GB/T 39786 的对应：系统等级越高，所用密码模块的等级要求越高（通常第一/二级系统要求模块一级及以上、第三级要求二级及以上、第四级要求三级及以上——以标准正文与密评细则为准）。

## 8. 常见误区

| 误区 | 事实 |
| --- | --- |
| "用了国密算法 = 合规" | 合规判定对象是**持证的模块/产品**，不是算法名 |
| "开源库包一层就是密码模块" | 模块边界、自测试、文档都要按 GB/T 37092 过检，或整体嵌入持证模块 |
| "软件实现拿不了证" | 能（一、二级），三级以上实际依赖硬件形态 |
| "一张证书全系列通用" | 证书绑定型号/版本/算法/等级，逐项核对 |
| "等级越高越好" | 等级与成本、交付复杂度正相关，按系统等级匹配即可 |
