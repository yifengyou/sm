# 行业应用画像

同样的算法，在不同行业的"组合方式"截然不同。本章按行业给出典型国密技术栈画像与改造要点，供选型与对标。

## 1. 金融：最成熟的国密生产环境

金融是国密改造的先行者（监管驱动 + 密评覆盖 + 高价值防护需求）：

| 场景 | 典型国密栈 |
| --- | --- |
| 金融 IC 卡 | **PBOC 3.0** 规范（2013）引入基于国密的借记/贷记应用：卡片 COS 内 SM2/SM3/SM4，交易用 SM2 离线签名/加密，防插播复制 |
| 网上银行 / 手机银行 | CFCA 签发的 SM2 双证书 + UKey/协同签名；传输层 TLCP；报文数字信封（GB/T 35275 风格） |
| 支付报文交换 | 网关间国密 IPSec/SSL VPN + 应用层 SM2 签名防抵赖 |
| 密码基础设施 | 金融数据密码机（GM/T 0045 等产品规范）集群 + HSM 管理体系 |

金融行业的特点：**密钥管理极度制度化**（KMC 托管、双人复核）、性能要求苛刻（支付峰值下 SM2 验签吞吐靠密码机横向扩展）、CFCA 的证书生态自成体系（配套 SADK 等私钥封装格式，见消息语法章）。

## 2. 政务：密评牵引的规范化市场

- **一网通办/政务服务平台**：统一身份认证（SM2 证书/UKey）、电子证照（OFD + GB/T 38540 电子签章）、电子印章系统；
- **政务云与政务外网**：国密 VPN（GM/T 0022/0024 体系）组网 + 业务系统 TLCP 化；
- **电子公文**：版式 OFD（GB/T 33190）承载，签章与时间戳全链国密；
- 驱动力：等保三级 + **密评强制**（政务系统普遍定级三级以上），"密码应用方案先行评估"在多地已成为立项前置条件。

## 3. 物联网与车联网

物联网的国密选型核心矛盾是**设备资源受限 vs 证书体系重量**：

| 方案 | 适用 |
| --- | --- |
| SM2 轻量证书 + DTLS 类通道 | 中等资源设备（网关、智能表计） |
| **SM9 标识密码** | 海量弱设备——设备 ID 即公钥，免证书分发（见 SM9 章） |
| 国密 SE 芯片（SM1/SM4 硬件） | 电表、POS、车载单元等成本敏感终端 |
| 平台侧密码服务 | 设备侧只做轻量运算，重密码运算上收平台 |

行业实例：

- **电力**：用电信息采集系统大规模采用国密芯片（表内 ESAM 安全模块做 SM4 加密与 SM3 校验），电力监控系统按"安全分区 + 国密纵向加密"组织防护；
- **车联网**：C-V2X 直连通信的消息层安全要求采用商密证书体系（假名证书轮换防追踪），车云通道走国密 TLS；
- **智能门锁/摄像头**：固件签名（SM2）防刷机 + 视频流 SM4 加密 + 平台 SM9 分发密钥的组合日趋常见。

**安防视频监控（GB 35114-2017，强制国标）**——视频监控是国密少有的**强制国标**落地场景（雪亮工程、AI 安防带动规模化部署），自成一套体系：

- 标准定位：公共安全视频监控联网的信息安全要求，覆盖设备认证、信令与视频流的加密/完整性、密钥管理全链；视频编码层与 GB/T 25724（SVAC）生态配合；
- 密码用法：设备/平台双向证书认证（SM2），信令 HMAC-SM3/SM2 签名，视频流 SM4 加密（视音频数据 + SVAC 加密头），密钥经由**VKEK（视频密钥加密密钥）**层层包裹下发——本质是"数字信封 + 分层密钥"的国密标准动作在视频域的实例化；
- 工程要点：老系统多是 GB/T 28181（联网协议）+ 明文流，向 35114 迁移时设备端需带安全模块（芯片内 SM4/SM3），平台侧补 CA/密钥管理；密评与安防行业检测（公安部检测中心）双轨要求下，新建系统直接按 35114 设计比改造便宜。

## 4. 电信

- **空口与核心网**：LTE/5G 终端与基带的第三套算法 128-EEA3/128-EIA3（ZUC，见 ZUC 章），中国市场设备默认支持；
- **SIM/eSIM**：卡 COS 内置国密算法族，运营商业务（如 andUAF 类认证框架）逐步国密化；
- 运营商自身业务系统（营业、计费）的改造路径与政务类似：等保定级 → 39786 建设方案 → 密评。

## 5. 区块链

联盟链是国密的天然用户（国内合规要求 + 联盟治理匹配 KGC/PKI 语义）：

| 层 | 国密替换 |
| --- | --- |
| 交易签名 | 节点/用户身份用 SM2（证书或密钥对） |
| 区块头/交易摘要 | SM3（Merkle 树哈希函数替换） |
| 节点间共识/P2P 通道 | TLCP 或国密 IPSec |
| 链上隐私数据 | SM4 字段级加密 + 数字信封授权解密 |
| 国密+标识 | 少数链用 SM9 做链上标识（DID）密钥体系 |

FISCO BCOS、长安链（ChainMaker）等主流国产联盟链均提供国密算法套件开关。**注意事项**：换算法意味着换地址编码与签名验证逻辑，存量链升级要过硬分叉/兼容流程；跨链交互时算法族不一致是常见对接障碍。

## 6. 医疗

- 电子病历/电子处方：SM2 签名（医师身份 + 时间戳）落实《电子签名法》要求（可靠电子签名四要件的技术映射见第四部分）；
- 医保结算通道：国密 VPN + 报文签名；
- 影像数据（DICOM）加密：字段级 SM4 或存储级 XTS/GCM。

## 7. 即时通信与协同办公

加密 IM 与协同办公是国内 TO B 场景的活跃地带（政务办公、金融内部协同）：

| 层 | 国密实践 |
| --- | --- |
| 传输通道 | TLCP / TLS 1.3 国密套件 |
| 端到端消息 | "SM2 密钥协商 + SM4 会话加密"的混合构造，密钥更新借鉴双棘轮（Double Ratchet）思想做前向保密（无统一国标，各家自研协议为主） |
| 身份 | SM2 证书 / SIM-Key / 设备标识（SM9，见 SM9 章） |
| 存储 | 消息落库 SM4 字段加密 + 密钥信封化；审计日志 SM3 链式完整性 |
| 音视频 | SRTP 类方案的国密替换（SM4-CTR/GCM + HMAC-SM3） |

- E2EE 没有国标协议，选型时重点审查两件事：**密钥协商的安全属性**（前向保密、降级保护）与**服务端可见面**（是否真端到端，还是只加密了传输层）；
- **邮件**：GB/T 35275 的 SignedData/EnvelopedData 可直接承载 S/MIME 风格的邮件加密与签名，国内实践集中在政务公文交换与等保三级邮件网关；消费级邮箱生态仍是国际算法的天下；
- 这类系统的密评要点与通用系统一致（通道、存储、鉴别、抗抵赖、随机数），额外关注**密钥更新频率**是否支撑"前向保密"的宣称。

## 8. 跨行业共性：改造的"标准动作"

把各行业经验收敛为一个通用改造清单：

```text
1. 定级与范围：等保级别、是否关基/行业监管细则、密评时间表
2. 资产盘点：传输通道（对外/内部/第三方）、存储数据（库/文件/备份）、
   身份鉴别（人/设备/系统间）、抗抵赖点（签名/时间戳）、随机数来源
3. 架构设计：密码服务集中化（密码机/密码服务平台），密钥三层架构
4. 证书体系：自建 CA（政务/金融大机构）vs 采购第三方签发（多数项目）
5. 迁移节奏：双算法并行 → 灰度切换 → 存量数据信封化重加密
6. 验收：KAT/互操作测试 → 预评 → 密评 → 整改闭环
```
