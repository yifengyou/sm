# 安全接入协议族与 WAPI

TLCP 之外，国密还有两条接入协议线：**VPN 协议族**（GM/T 0022 IPSec、GM/T 0024 SSL VPN）与**无线局域网的 WAPI**——后者是 SM4 的诞生地，也是国密历史上最曲折的一页。

## 1. 国密 IPSec VPN（GM/T 0022-2014）

IPSec VPN 用于网络层（L3）的站点互联与远程接入，国密化要点是在 IKE/ESP 中全面替换算法：

| 协议位置 | 国际实现 | 国密实现（GM/T 0022） |
| --- | --- | --- |
| IKE 身份认证 | RSA/ECDSA 证书/预共享密钥 | **SM2 证书 + SM2WithSM3 签名**（或预共享密钥） |
| IKE 密钥交换 | DH（MODP/ECP） | SM2 密钥协商 / ECDHE-SM2 |
| ESP 加密 | AES-CBC/GCM | **SM4-CBC/GCM** |
| ESP 完整性 | HMAC-SHA | **HMAC-SM3** |
| PRF | SHA 系列 | SM3 构造 |

对接要点（网关间互联的实战经验）：

- 阶段一（IKE SA）：两端算法套件、DH 组、身份标识（证书 DN 或 IP）必须逐项对齐，国密网关对"身份载荷格式"的实现差异较多；
- 阶段二（IPSec SA）：感兴趣流、PFS（DH 组）配置；
- 互操作的现实困境：**GM/T 0022 基于 IKEv1 框架**，与国际主流 IKEv2 生态存在代差，跨厂商对接时以双栈网关（同时支持国密与国际套件）过渡；
- 产品合规：IPSec VPN 网关属于商用密码产品认证目录内产品，采购核验证书；
- 配套国标 **GB/T 32922-2016《IPSec VPN 安全接入基本要求与实施指南》**给出部署层面的要求（网关自身防护、审计、密钥管理）。

## 2. 国密 SSL VPN（GM/T 0024-2014）与 TLCP 的关系

```text
GM/T 0024-2014《SSL VPN 技术规范》
  ├── 应用层封装的 SSL 协议（双证书握手）
  ├── 网关互联的扩展：站点到站点模式、设备身份、专用告警
  │   （TLCP 至今保留的 200~205 号告警即源于此）
  └── 套件命名历史（ECC_SM1_SM3={E0,01} 等以 SM1 为默认）
        │
        ▼ 收敛、标准化
GB/T 38636-2020（TLCP）—— 传输层通用化，SM4 套件为主，SM1 套件遗留兼容
```

现存 SSL VPN 网关（密码产品目录内）多数同时说"GM/T 0024 模式"与"TLCP 模式"——对接老网关时先确认它支持的套件列表（是否只有 CBC、是否有 SM1）。站点到站点（gateway-to-gateway）的国密隧道至今大量运行在 0024 体系的设备之间。

## 3. WAPI：SM4 的诞生地

WAPI（WLAN Authentication and Privacy Infrastructure，无线局域网鉴别与保密基础结构）是中国提出的无线局域网安全体系，也是理解 SM4 历史的钥匙：

```text
2003        WAPI 方案提出，作为 IEEE 802.11i（WPA 所基于）之外的中国路线
            ├── WAI（鉴别基础设施）：三元对等鉴别（TePA-AC），ASU 服务器
            │   参与的实体双向鉴别，替代 802.11i 的四次握手/802.1X 体系
            └── WPI（保密基础设施）：数据保密采用 SMS4 分组算法
2006–2008   WAPI 成为强制性国家标准（GB 15629.11 系列），引发激烈的国际标准博弈
            （与 IEEE 802.11i 的路线之争是当年 ISO/IEC 层面的标志性事件）
2010s       WAPI 进入 ISO/IEC 8802-11 体系（曲折落定）；产业化聚焦政务、运营商、
            电力等专网场景
2012        SMS4 以 GM/T 0002-2012 公开发布，更名 SM4——算法从"WAPI 专属"
            走向通用商密主力
2016        SM4 升格 GB/T 32907；2021 进入 ISO/IEC 18033-3
```

技术遗产与现状：

- **SM4 的第一份公开规范就出自 WAPI 生态**（SMS4 之名即从 WAPI 实施细则流出），今日 SM4 与 WAPI 的历史绑定常被新人忽视；
- WAPI 的三元对等鉴别（TePA）思想后来发展为独立的实体鉴别标准族：国内 GB/T 15843《信息安全技术 实体鉴别》系列（与国际标准 ISO/IEC 9798 各部分对应，覆盖对称加密、数字签名、密码校验函数、零知识等机制），TePA 机制本身亦进入 ISO/IEC 9798-10（TTP 辅助的实体鉴别）；
- 现实部署：运营商 WLAN、政务专网、电力等存量场景仍在运行 WAPI（配套的鉴别服务器 ASU、WAPI 证书体系自成一体）；消费级 Wi-Fi 生态则是 WPA2/WPA3 的天下；
- 对工程者：新项目几乎不会从零建 WAPI，但**涉及存量专网接入改造时**要能识别 WAPI 术语（ASU、USK/MSK 会话密钥层次、WPI 套件）。

## 4. SSH 与远程运维通道的国密化

密评对"设备和计算安全"有专门检查项：**远程管理通道必须加密**——生产环境里这条几乎都落在 SSH 上。SSH 的国密化没有公开的全国性协议标准，工程上是三条路线：

| 路线 | 做法 | 适用 |
| --- | --- | --- |
| 网关替代 | 运维流量不走原生 SSH，改走国密 VPN（IPSec/SSL VPN）或零信任网关（SPA 敲门 + TLCP 控制面，见下节） | 大多数密评整改项目的选择 |
| 持证 SSH 类产品 | 采购带商用密码产品认证证书的 SSH 安全网关/堡垒机：记录层 SM4、完整性 HMAC-SM3、身份 SM2 证书/UKey | 金融/政务集中运维 |
| OpenSSH 私有扩展 | 自编译 OpenSSH，在算法协商中插入 SM 系套件（社区有零散 patch，无官方支持） | 内部实验/特殊环境过渡 |

- 路线三的代价要说透：互操作性差（各 patch 各自为政）、版本升级困难、**无认证证书，在密评中不构成合规依据**；
- 堡垒机形态的价值除了加密还有**审计**：运维指令留痕（SM3 链式完整性/HMAC-SM3）正好对应密评"日志记录完整性"检查项；
- 联动检查：SSH 国密化后，主机密钥（SM2）与会话密钥（SM4）同样要过"密钥不出设备、随机源合规"两道检查（见密钥管理与随机数章）。

## 5. 接入场景总表与零信任

| 场景 | 首选国密协议 | 备注 |
| --- | --- | --- |
| Web/App 到服务端 | TLCP（双证书）或 TLS1.3+RFC 8998 | 见 TLCP 章 |
| 站点到站点专线 | 国密 IPSec / SSL VPN 网关互联 | 设备认证+批量加密 |
| 远程办公接入 | 国密 IPSec VPN 客户端 / 零信任网关 | 客户端软件需国密改造 |
| 远程运维/堡垒机 | 国密 SSH 安全网关 / 堡垒机（SM4 记录层 + 审计完整性） | 或以 VPN/零信任网关替代原生 SSH |
| 无线专网 | WAPI（存量） | 新建多为 WPA3+上层国密 |
| IoT 设备接入 | DTLS 类国密改造 / SM2 证书双向认证 + SM4-GCM | 轻量证书（见应用章） |

**零信任（SDP/SPA）的国密化**：主流做法是在零信任网关的"先认证后连接"流程中替换凭据体系——SPA敲门包用 SM4-GCM 加密、用户/设备身份用 SM2 双证书、控制面走 TLCP、持续评估的设备指纹用 HMAC-SM3 防篡改。协议框架不变，密码全换——这再次印证国密改造的基本盘是"算法槽位化"。
