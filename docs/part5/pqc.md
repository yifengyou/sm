# 后量子时代的国密

量子计算对密码体系的威胁是**差异化**的：Shor 算法击穿所有基于大整数分解/离散对数（含椭圆曲线）的公钥密码，Grover 算法则只把对称与杂凑的有效强度开平方。落到国密算法族上：

| 算法 | 数学根基 | 量子威胁 |
| --- | --- | --- |
| SM2（签名/加密/交换） | ECDLP（椭圆曲线） | **致命**（Shor 多项式时间可解） |
| SM9（IBC） | BN 曲线 + 双线性对（仍属 ECDLP 家族） | **致命** |
| SM4 | 分组密码 | 缓和：Grover 使穷举从 2¹²⁸ 降至约 2⁶⁴ 次量子操作（代价高、串行性强，实际威胁有限但需纳入长期规划） |
| SM3 | 杂凑 | 缓和：原像搜索降至 2¹²⁸（Grover），碰撞搜索降至约 2¹⁷¹（BHT 类算法）——256 位摘要的碰撞强度仍高于 128 位级别 |
| ZUC-128 | 序列密码 | 同 SM4（128 位密钥量级）；**ZUC-256 把密钥扩到 256 位**，即是对 Grover 的直接回应 |

时间尺度的关键概念是 **HNDL（先截获、后解密）**：对手今天录下你的 SM2 加密流量，等量子计算机可用时回溯解密。因此迁移优先级不取决于量子机器何时到来，而取决于**数据的保密寿命**——十年后仍然敏感的通道（政务、医疗、工业机密）需要最早迁移。

## 1. 国际 PQC 标准格局（2024–2026 已定盘的部分）

- **FIPS 203 ML-KEM**（Kyber 系）：密钥封装——TLS 混合密钥交换的主力；
- **FIPS 204 ML-DSA**（Dilithium 系）：通用签名；
- **FIPS 205 SLH-DSA**（SPHINCS+ 系）：基于哈希的保守备份签名；
- 2025 年 NIST 增选 **HQC** 作为 KEM 的第二路线（与 ML-KEM 不同数学根基的备份），基于码的方案补位；FN-DSA（Falcon 系）等在后续管线中；
- **TLS 1.3 混合部署已成事实标准**：`X25519MLKEM768` 自 2024 年起被主流浏览器（Chrome/Firefox/Safari）与大型站点默认启用，OpenSSL 3.5 起将其置于默认组列表首位——"经典 + PQC"双算法并用，单一算法被击穿时另一条腿仍站立。

**工程数据**（选型必看的尺寸账，FIPS 203 Table 3 / FIPS 204 Table 2 官方值）：

| 算法 | 公钥 | 私钥 | 密文/签名 | 对照 |
| --- | --- | --- | --- | --- |
| ML-KEM-512 / 768 / 1024 | 800 / 1184 / 1568 B | 1632 / 2400 / 3168 B | 768 / 1088 / 1568 B（密文） | ECDH P-256：公钥 65 B |
| ML-DSA-44 / 65 / 87 | 1312 / 1952 / 2592 B | 2560 / 4032 / 4896 B | 2420 / **3309** / 4627 B（签名） | SM2/P-256 签名：64 B（裸） |
| SLH-DSA-128s | 32 B | 64 B | ≈7856 B | 签名是 ECDSA 的 ~120× |

三个预算结论：ML-DSA-65 签名约为 ECDSA 的 **50 倍**，一条 ML-DSA 签发的证书链（3~4 张）会让握手多出数十 KB（超过单包 MTU，UDP 类协议如 DNSSEC 要考虑分片）；ML-KEM 尺寸对 TLS 握手影响轻微（+2 KB 量级），这正是混合 KEM 先行落地的原因；HSM/密码卡对 ML-DSA 的支持在 2026 年仍有限（软件栈先行），合规设备采购周期要提前考虑。

## 2. 国密侧的进展与生态

- 国内团队深度参与了国际 PQC 征程（NIST 历轮征集中有 LAC、Aigis 等中国方案），并通过全国性商用密码算法设计竞赛等机制持续孵化抗量子候选；
- 商用密码体系的后量子标准由密标委按程序推进（截至撰写仍在过程中，**以密标委/国家密码管理局公告为准**——本文不预测编号）；
- 工程生态已就位：gmsm 等库同时提供 SM 系与 ML-KEM/ML-DSA/SLH-DSA，并支持 **TLS 1.3 混合密钥交换**；OpenSSL 3.5+ 原生 ML-KEM/ML-DSA。也就是说，"国密栈 + 后量子栈"同库共存的技术前提已经成熟；
- 合规语境注意：PQC 算法目前**不属于商密认证算法族**，在强制商密场景里应作为"叠加增强"而非"替代"引入（混合模式恰好为此而生）。

## 3. 混合化：现实中的迁移形态

```text
混合 KEM（密钥交换），构造要点是"拼接后统一进 KDF"：
  ss_classic = ECDH( SM2 / X25519 )
  ss_pqc     = ML-KEM-768 封装秘密
  shared_secret = KDF( ss_classic ‖ ss_pqc )     # TLS 1.3 走 HKDF-Extract
  ——任意一半被击穿（今天的 ECDLP 攻击 或 未来的 Shor），另一半仍保机密性；
    两条腿独立计算、独立编码后拼接，不是"发明新算法"

混合证书/签名（演进中形态）：
  同一实体并行持有 SM2 证书与 ML-DSA 证书，按对端能力选择或双签
```

国密语境的混合形态即 `KDF(SM2-ECDH ‖ ML-KEM)`：SM2 侧沿用 curveSM2 的 ECDHE 份额与（TLCP 场景的）双证书体系，ML-KEM 份额作为并列组（composite group）进入协商——工程上就是"多一个密钥交换组"的密码敏捷性问题，这也是第 4 节清单的第一条为何是算法标识可配置。

落地建议排序：

1. **长期机密通道**（HNDL 敏感）：最先引入混合 KEM；
2. **签名/证书**：签名不存在 HNDL（伪造需要实时量子机），迁移紧迫性低一档，等标准与 CA 生态；
3. **对称体系**：保密寿命 >20 年的数据，规划 ZUC-256/更大密钥量的对称方案；SM3 的 256 位输出在可见周期内够用（即使 BHT 类量子碰撞搜索下界也在 2¹⁷¹），真正的对称侧动作是把密钥量升到 256 位档；
4. SM9 体系用户最需要预案：其 KGC 模式叠加 Shor 威胁，密钥体系重建成本高，宜提前设计"标识体系不变、密码底层可换"的抽象层。

## 4. 密码敏捷性：这次迁移的真正教训

PQC 迁移的工程瓶颈从来不是算法，而是**可替换性**。把教训固化成清单：

```text
□ 算法标识可配置（套件/协商机制驱动，而不是散落在代码里的硬编码）
□ 密文/签名格式的版本字段（为"第三种算法"留位）
□ 证书体系支持并行双证书
□ 密钥对象抽象（软/硬/混合密钥同接口）
□ 存量数据的再加密通道（信封化重加密能力常备）
□ 算法库存清单：每个通道/每类数据的算法、密钥长度、负责人、寿命评估
```

历史上从 MD5→SHA、RSA→ECDSA、TLS1.0→1.3 的每次迁移，代价最大的系统都是"算法焊死在协议与存储格式里"的系统。国密改造本身就是一次全体系密码敏捷性演练——把这次改造形成的开关与抽象层保留好，它就是未来 PQC 迁移的预案。
