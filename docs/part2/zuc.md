# ZUC 祖冲之序列密码算法

ZUC（祖冲之，数学家祖冲之命名）是国密体系中的**序列密码（流密码）**，面向无线通信设计，是 3GPP LTE 的第三套保密性/完整性算法 **128-EEA3 / 128-EIA3** 的内核（与 SNOW 3G、AES 并列）。标准体系：

| 标准 | 名称 |
| --- | --- |
| GM/T 0001.1-2012 / GB/T 33133.1-2016 | 算法描述（本章主体） |
| GM/T 0001.2-2012 / GB/T 33133.2-2021 | 保密性算法（128-EEA3） |
| GM/T 0001.3-2012 / GB/T 33133.3-2021 | 完整性算法（128-EIA3） |
| GM/T 0001.4-2024 | 鉴别式加密机制（GXM/MUR 两种 AEAD 模式） |
| 3GPP TS 35.221 / ETSI SAGE 文档 1~4 | 3GPP 侧规范与测试数据 |
| ISO/IEC 18033-4:2011/Amd 1:2020 | 流密码国际标准补篇 |

> 注意 ZUC 的行标与国标编号**不同源**（GM/T 0001 ↔ GB/T 33133），引用时容易张冠李戴。

输入为 128 位密钥 K 与 128 位初始向量 IV，输出 32 位一拍的密钥字流。本章全部公式与测试向量均已依据 GM/T 0001 官方文本（含英译本）及参考实现逐项复核。

## 1. 总体架构：三层流水线

```text
      128-bit Key + 128-bit IV
              │ 密钥装入（k‖d‖iv）
              ▼
┌─────────────────────────────────────────────┐
│  LFSR：16 个 31 比特单元 s0…s15              │  ←── 线性层（极大周期）
│  定义在素域 GF(2³¹−1) 上，模 (2³¹−1) 加法反馈  │
└──────────────┬──────────────────────────────┘
               │ 抽取 8 个单元的 128 位
               ▼
┌─────────────────────────────────────────────┐
│  BR（比特重组）：组装 4 个 32 位字 X0…X3      │  ←── 桥接层
└──────────────┬──────────────────────────────┘
               │ X0,X1,X2 进非线性函数；X3 直接参与输出
               ▼
┌─────────────────────────────────────────────┐
│  F（非线性函数）：2 个 32 位记忆单元 R1,R2    │  ←── 非线性层
│  Z = W ⊕ X3  ──► 每拍输出一个 32 位密钥字     │
└─────────────────────────────────────────────┘
```

"线性极大周期 + 非线性混淆"的经典流密码布局：LFSR 保证长周期与统计均匀，F 部件（带记忆的有限状态机）抵抗代数与统计攻击。

## 2. LFSR：素域上的 16 级移位寄存器

### 2.1 反馈与更新

LFSR 由 16 个 31 比特单元 s₀…s₁₅ 构成，运算定义在**梅森素域 GF(2³¹ − 1)** 上（模 p = 2³¹ − 1 的加法/乘法）。特征多项式：

```text
f(x) = x¹⁶ − (2¹⁵·x¹⁵ + 2¹⁷·x¹³ + 2²¹·x¹⁰ + 2²⁰·x⁴ + (2⁸ + 1))
```

是 GF(2³¹−1) 上的**本原多项式**，保证状态序列周期极大（理论量级 (2³¹−1)¹⁶）。

每拍计算新单元：

```text
v = 2¹⁵·s₁₅ + 2¹⁷·s₁₃ + 2²¹·s₁₀ + 2²⁰·s₄ + (1 + 2⁸)·s₀   (mod 2³¹−1)
```

然后按模式更新：

```text
初始化模式 LFSRWithInitialisationMode(u)：        工作模式 LFSRWithWorkMode()：
  s₁₆ = (v + u) mod (2³¹−1)                         s₁₆ = v mod (2³¹−1)
  若 s₁₆ = 0 则 s₁₆ = 2³¹−1                          若 s₁₆ = 0 则 s₁₆ = 2³¹−1
  (s₁,…,s₁₆) → (s₀,…,s₁₅)                           (s₁,…,s₁₆) → (s₀,…,s₁₅)
```

（移位方向：新 s₀ = 旧 s₁，新进入的 s₁₆ 放在最右端。）

**素域选型的工程含义**：与 SNOW 3G 建在 GF(2³²) 扩域（需要模乘/带进位乘）不同，ZUC 的模 2³¹−1 运算只需**加法 + 溢出回卷**：

```c
uint32_t addm(uint32_t a, uint32_t b) {          // 模 (2^31−1) 加
    uint32_t c = a + b;
    return (c & 0x7FFFFFFF) + (c >> 31);          // 进位回卷（一次即可，因 a,b < p）
}
uint32_t mul_pow2(uint32_t x, int k) {            // 乘 2^k mod (2^31−1)＝31 位循环左移
    return ((x << k) | (x >> (31 - k))) & 0x7FFFFFFF;
}
```

这使 ZUC 的硬件面积与功耗显著优于扩域方案，适合基站/终端基带。

### 2.2 密钥装入

128 位密钥 k₀‖…‖k₁₅ 与 128 位 IV iv₀‖…‖iv₁₅（各 8 比特）经一组 **15 比特常量 D** 装入 LFSR：

```text
sᵢ = kᵢ ‖ dᵢ ‖ ivᵢ        # kᵢ 占高 8 位、dᵢ 占中 15 位、ivᵢ 占低 8 位，共 31 位
```

D 的 16 个 15 比特常量（标准原文以二进制给出，此处换算为十六进制）：

```text
d0..d7  : 44D7  26BC  626B  135E  5789  35E2  7135  09AF
d8..d15 : 4D78  2F13  6BC4  1AF1  5E26  3C4D  789A  47AC
```

## 3. BR（比特重组）

从 8 个 LFSR 单元抽取 128 位组装成 4 个 32 位字（H/L 表示 31 位单元的高/低 16 位）：

```text
X₀ = s₁₅H ‖ s₁₄L        X₁ = s₁₁L ‖ s₉H
X₂ = s₇L  ‖ s₅H         X₃ = s₂L  ‖ s₀H
```

设计意图：BR 从线性层抽取的位**跨单元交错**（15/14、11/9、7/5、2/0），使任何单个单元的位只能进入一个固定字节位段，F 部件一轮即可消费全部 16 个单元的信息。

## 4. F：非线性函数

F 是带 2 个 32 位记忆单元 R₁、R₂ 的有限状态机（初值 0）：

```text
W  = (X₀ ⊕ R₁) ⊞ R₂          # ⊞ 为模 2³² 加
W₁ = R₁ ⊞ X₁                 # 模 2³² 加
W₂ = R₂ ⊕ X₂                 # 按位异或
R₁ = S( L₁( W₁L ‖ W₂H ) )
R₂ = S( L₂( W₂L ‖ W₁H ) )
Z  = W ⊕ X₃                   # 工作阶段的密钥字输出
```

其中 W₁L/W₂H 表示取低/高 16 位拼接成 32 位；L₁/L₂ 为循环移位线性变换：

```text
L₁(X) = X ⊕ (X⋘2) ⊕ (X⋘10) ⊕ (X⋘18) ⊕ (X⋘24)
L₂(X) = X ⊕ (X⋘8) ⊕ (X⋘14) ⊕ (X⋘22) ⊕ (X⋘30)
```

S 为 4 个 8×8 S 盒并行：**S = (S₀, S₁, S₀, S₁)**，按字节从高到低交替使用 S₀/S₁（两个 256 字节常量表，见标准附录 A /本章参考实现）。

> **实现者最易踩的三个坑**（对照多个开源实现的 bug 记录）：
> 1. W₁ 是**模加**不是异或、W₂ 是**异或**不是模加（两处运算类型相反）；
> 2. L₂ 有 **五项**（含 ⋘30），常被误写成四项；
> 3. S 盒按字节位置交替 S₀/S₁，不是全用 S₀。

## 5. 运行流程

```text
初始化阶段（32 拍）：
  repeat 32 次：
      BitReconstruction()
      W = F(X₀, X₁, X₂)
      LFSRWithInitialisationMode( W ≫ 1 )      # 注意：F 的输出右移 1 位后进入 LFSR
丢弃阶段（1 拍）：
      BitReconstruction(); F(X₀,X₁,X₂); LFSRWithWorkMode()   # F 输出丢弃
密钥流阶段（每拍）：
      BitReconstruction()
      Z = F(X₀, X₁, X₂) ⊕ X₃
      LFSRWithWorkMode()
```

初始化的 32 拍把密钥与 IV 在"非线性 F ↔ 线性 LFSR"之间来回搅拌 32 轮，实现充分扩散；随后丢弃一拍输出，避免初始状态弱信息直接进入密钥流。

## 6. 参考实现（Python，已通过官方全部向量）

```python
import struct
P = (1 << 31) - 1

def addm(a, b):
    c = a + b
    return (c & 0x7FFFFFFF) + (c >> 31)

def mul_pow2(x, k):
    return ((x << k) | (x >> (31 - k))) & 0x7FFFFFFF

def rol32(x, k):
    return ((x << k) | (x >> (32 - k))) & 0xFFFFFFFF

S0 = bytes.fromhex(
    "3e725b47cae0003304d1549809b96dcb" "7b1bf932af9d6aa5b82dfc1d08530390"
    "4d4e8499e4ced991ddb685488b296eac" "cdc1f81e734369c6b5bdfd396320d438"
    "767db2a7cfed57c5f32cbb142106559b" "e3ef5e314f7f5aa40d8251495fba581c"
    "4a16d517a892241f8cffd8ae2e01d3ad" "3b4bda46ebc9de9a8f87d73a806f2fc8"
    "b1b437f70a2213287ccc3c89c7c39656" "07bf7ef00b2b975235417961a64c10fe"
    "bc2695888ab0a3fbc01894f2e1e5e95d" "d0dc1166645cec59427512f5749caa23"
    "0e86abbe2a02e767e644a26cc2939ff1" "f6fa36d250689e6271153dd640c4e20f"
    "8e83776b25053f0c30ea70b7a1e8a965" "8d271adb81b3a0f4457a19dfee783460")
S1 = bytes.fromhex(
    "55c263713bc847869f3cda5b29aafd77" "8cc5940ca61a1300e3a8167240f9f842"
    "4426689681d9453e1076c6a78b3943e1" "3ab5562ac06db3052266bfdc0bfa6248"
    "dd20110636c9c1cff62752bb69f5d487" "7f844cd29c57a4bc4f9adffed68d7aeb"
    "2b53d85ca11417fb23d57d3067730809" "eeb7703f61b2198e4ee54b938f5ddba9"
    "adf1ae2ecb0dfcf42d466e1d97e8d1e9" "4d37a5755e839eab829db91ce0cd4989"
    "01b6bd5824a25f387899159050b895e4" "d091c7ceed0fb46fa0ccf0024a79c3de"
    "a3efea51e66b18ec1b2c80f774e7ff21" "5a6a541e41319235c433070aba7e0e34"
    "88b1987cf33d606c7bcad31f32650428" "64be859b2f598ad7b025acaf1203e2f2")
D = [0x44D7, 0x26BC, 0x626B, 0x135E, 0x5789, 0x35E2, 0x7135, 0x09AF,
     0x4D78, 0x2F13, 0x6BC4, 0x1AF1, 0x5E26, 0x3C4D, 0x789A, 0x47AC]

def L1(x): return x ^ rol32(x, 2) ^ rol32(x, 10) ^ rol32(x, 18) ^ rol32(x, 24)
def L2(x): return x ^ rol32(x, 8) ^ rol32(x, 14) ^ rol32(x, 22) ^ rol32(x, 30)

def S(w):
    b = [(w >> 24) & 0xFF, (w >> 16) & 0xFF, (w >> 8) & 0xFF, w & 0xFF]
    o = [S0[b[0]], S1[b[1]], S0[b[2]], S1[b[3]]]
    return (o[0] << 24) | (o[1] << 16) | (o[2] << 8) | o[3]

class ZUC:
    def __init__(self, key, iv):
        assert len(key) == 16 and len(iv) == 16
        self.s = [(key[i] << 23) | (D[i] << 8) | iv[i] for i in range(16)]
        self.R1 = self.R2 = 0
        for _ in range(32):
            self._br(); w = self._f()
            self._lfsr(lambda: None, u=w >> 1)
        self._br(); self._f()          # 丢弃一拍
        self._lfsr()

    def _br(self):
        s = self.s
        self.X0 = (((s[15] >> 15) & 0xFFFF) << 16) | (s[14] & 0xFFFF)
        self.X1 = ((s[11] & 0xFFFF) << 16) | (s[9] >> 15)
        self.X2 = ((s[7] & 0xFFFF) << 16) | (s[5] >> 15)
        self.X3 = ((s[2] & 0xFFFF) << 16) | (s[0] >> 15)

    def _f(self):
        W  = ((self.X0 ^ self.R1) + self.R2) & 0xFFFFFFFF
        W1 = (self.R1 + self.X1) & 0xFFFFFFFF
        W2 = self.R2 ^ self.X2
        u = L1(((W1 << 16) & 0xFFFFFFFF) | (W2 >> 16))
        v = L2(((W2 << 16) & 0xFFFFFFFF) | (W1 >> 16))
        self.R1, self.R2 = S(u), S(v)
        return W

    def _lfsr(self, dummy=None, u=None):
        s = self.s
        v = s[0]
        v = addm(v, mul_pow2(s[0], 8))     # (1+2^8)·s0 = s0 + 2^8·s0
        v = addm(v, mul_pow2(s[4], 20))
        v = addm(v, mul_pow2(s[10], 21))
        v = addm(v, mul_pow2(s[13], 17))
        v = addm(v, mul_pow2(s[15], 15))
        if u is not None:
            v = addm(v, u)
        self.s = s[1:] + [v if v else P]

    def next_word(self):
        self._br()
        z = self._f() ^ self.X3
        self._lfsr()
        return z
```

## 8. 保密性算法 128-EEA3（GB/T 33133.2）

EEA3 = ZUC 密钥流与明文按位异或，与所有流密码一样加密解密同体。3GPP 场景的 IV 构造（GB/T 33133.2 附录 A.2）：

```text
COUNT（32 位计数值）→ IV[0..3]（大端）
IV[4]  = ((BEARER ≪ 1) | DIRECTION) ≪ 2        # 5 位承载 + 1 位方向 + 2 位 0
IV[5..7] = 0
IV[8..11] = IV[0..3]                            # COUNT 复写
IV[12] = IV[4]
IV[13..15] = 0
```

加密流程：以（CK, IV）初始化 ZUC，产生 ⌈LENGTH/32⌉ 个密钥字（LENGTH 为消息比特长度，不足整字低位补零后异或，只输出有效位）。

## 9. 完整性算法 128-EIA3（GB/T 33133.3）

EIA3 用 ZUC 密钥流构造 32 位 MAC，构造方式非常精巧（**置位窗口累加**）：

```text
L = ⌈LENGTH/32⌉ + 2
以（IK, IV）产生 32L 比特密钥流 k[0..32L−1]
kᵢ = k[i] ‖ k[i+1] ‖ … ‖ k[i+31]      # 从第 i 比特起的 32 位滑动窗口

T = 0
for i = 0 … LENGTH−1:
    若消息比特 M[i] = 1：T = T ⊕ kᵢ    # 只有置位位的位置触发窗口异或
T = T ⊕ k_LENGTH                        # 两个收尾窗口把长度绑进 MAC
MAC = T ⊕ k_{32×(L−1)}
```

安全性直觉：每个置位消息比特把一个"位置相关的 32 位密钥窗口"累进 MAC，MAC 对消息内容、位置、长度同时敏感；伪造需要预测密钥流窗口，等价于预测 ZUC 输出。

EIA3 的 IV 构造与 EEA3 不同（方向位以异或方式折叠进两个字节）：

```text
IV[0..3] = COUNT        IV[4] = BEARER ≪ 3        IV[5..7] = 0
IV[8] = IV[0] ⊕ (DIRECTION ≪ 7)
IV[9..11] = IV[1..3]    IV[12] = IV[4]  IV[13] = IV[5]
IV[14] = IV[6] ⊕ (DIRECTION ≪ 7)         IV[15] = IV[7]
```

**官方示例**（GM/T 0001.3 附录 B，均可用于实现自测）：

| 示例 | 参数 | MAC |
| --- | --- | --- |
| 1 | IK=00×16，COUNT=0，BEARER=0，DIR=0，LENGTH=1 bit，M=0 | `C8A9595E` |
| 2 | IK=`C9E6CEC4607C72DB000AEFA88385AB0A`，COUNT=`A94059DA`，BEARER=A，DIR=1，LENGTH=0x241=577 bit，M=72 字节 `983B41D4…93C53881` + 1 个 0 比特 | `FAE8FF0B` |

## 10. ZUC-256 与 AEAD 模式：面向 5G 与新一代应用的演进

- **ZUC-256**（草案，ZUC 设计团队 2018 年提出）：密钥扩展到 256 位、IV 为 184 位（23 字节），把 LFSR 扩到 31 级并新增 256 位密钥装入；MAC 支持四种长度（32/64/128/256 位），面向 5G 及 256 位安全套件场景。核心轮函数、S 盒、L₁/L₂ 与 ZUC-128 完全一致，属于"加宽不改构"的演进。
- **GM/T 0001.4-2024**：为 ZUC 定义了两种鉴别式加密（AEAD）模式，把 ZUC 从"纯流密码"推进到"带认证的加密"：
  - **GXM**（类 GCM）：单个流密码实例 + GHASH 认证标签（16 字节 H 密钥独立），用法与 GCM 几乎同构，nonce 复用同样致命；
  - **MUR**（抗误用）：双密钥（数据密钥 + 标签密钥）+ 合成 IV，IV 意外复用时不塌方，代价是两次流密码调用。
- Go 生态的 `emmansun/gmsm` 等库已实现 ZUC-128/256、EEA3/EIA3 与 GXM/MUR，可作为工程参照。

## 11. 安全性与实现要点

- **评估历史**：ZUC 1.0 版（2010）在 ETSI SAGE 的第三方评估中收到反馈后修订为 1.5（2011），修正了早期版本的统计弱点后才进入 3GPP——这段"公开评估—修订"的过程本身是密码算法标准化的范本；现行版本经受住了十余年公开密码分析。
- **统计性质**：S 盒与 L₁/L₂ 的选择使 F 部件达到最优差分/非线性指标量级；带记忆结构（R₁/R₂ 依赖历史）切断"单拍差分"的传播链。
- **实现**：
  - 31 位单元与模 2³¹−1 加法在硬件中极便宜（无乘法器），FPGA/ASIC 吞吐可达数 Gbps 级；
  - 软件优化方向是**多实例并行**（SIMD 同时跑 8/16 个 ZUC 实例，适合 EEA3 的计数器式使用）与 BR/查表融合；
  - 高速场景注意 EIA3 的滑动窗口 MAC 朴素实现是 O(32·LENGTH) 位运算，可用前缀异或/字并行技巧加速。

## 12. ZUC 与 SNOW 3G 对比

| 维度 | SNOW 3G（EEA1/EIA1） | ZUC（EEA3/EIA3） |
| --- | --- | --- |
| LFSR 域 | GF(2³²) 扩域，模乘反馈 | GF(2³¹−1) 素域，模加反馈 |
| 单元宽度 | 32 位 × 16 | 31 位 × 16 |
| 非线性层 | FSM（2 记忆单元 + S 盒） | F（2 记忆单元 + S 盒 + 双线性变换） |
| 硬件成本 | 较高（模乘） | 低（加法回卷） |
| 设计方 | ETSI SAGE（欧洲） | 中国（ZUC 设计组/数据通信科学技术研究所） |
| 3GPP 地位 | 第一套（欧洲主导市场） | 第三套（中国主导市场） |
