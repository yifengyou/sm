# SM1 与其他受限算法

国密体系里有一个"特殊成员"：SM1。它出现在几乎所有早期加密卡、加密机和安全芯片的产品手册里，但你找不到它的公开算法规范。本章说明 SM1 的定位、应用形态、以及围绕"算法不公开"的工程与合规注意事项。

## 1. SM1 的定位

| 属性 | 说明 |
| --- | --- |
| 类别 | 对称分组密码 |
| 分组/密钥长度 | 128 位分组（业界通行认知；算法未公开，规格以芯片手册为准） |
| 算法规范 | **不公开**——仅以 IP 核、芯片、加密卡等硬件形态交付 |
| 标准 | 无公开标准文本；产品按 GM/T 系列产品规范检测认证 |
| 安全强度 | 设计目标 128 位 |

SM1 与 SM4 是同一时期"一软一硬"的双轨设计：SM4（当时称 SMS4）随 WAPI 无线局域网体系公开，走标准算法路线；SM1 走封闭硬件路线，服务于对算法保密性有制度要求的场景。

## 2. 应用形态

SM1 从不出现在软件里，而是藏在以下载体中：

- **PCI-E 密码卡**：插在服务器上，通过 GM/T 0018（SDF）接口提供 SM1 加解密；
- **服务器密码机**：网络形态的密码服务集群，SM1/SM4 引擎并存；
- **安全芯片/SE**：金融 IC 卡、社保卡、ETC 等卡片操作系统（COS）内部；
- **加密 VPN 网关**：早期国密 SSL/IPSec VPN 设备的记录层（对应 GM/T 0024 时代的 `ECC_SM1_SM3` 等密码套件）；
- **POS/ATM 等金融终端**的密钥加密通道。

在 TLCP（GB/T 38636）的密码套件表里仍保留着 SM1 套件（如 `ECC_SM1_SM3 = {0xE0,0x01}`），但现代实现（Tongsuo、GmSSL 等）通常只实现 SM4 套件——SM1 套件只在配备相应硬件的专用网关间使用。

## 3. "算法不公开"的工程影响

**Kerckhoffs 原则**认为系统安全性不应依赖算法保密。SM1 的实践是一个刻意的例外，其代价与收益都很明确：

代价：

- **无法软件实现**：任何纯软件系统都无法使用 SM1，应用被绑定在特定硬件供应链上；
- **无法独立审计**：第三方无法对算法本身做密码分析，信任完全转移到产品检测认证制度上；
- **互操作受限**：两家厂商的 SM1 模块之间理论上是同规格的，但实际联调依赖检测机构背书而非代码级验证；
- **性能天花板**：吞吐取决于芯片，无法像 SM4 那样吃到 CPU 指令加速、AVX2 bitslicing 等软件优化红利。

收益：

- **对抗逆向与克隆**：算法只在芯片内运行，白盒提取与协议重实现攻击的难度显著提高；
- **配合密评与涉密体系**：在密钥管理要求极高的场景，"算法、密钥、运算全部封闭在硬件内"是最容易通过安全评估的形态。

工程判断题：**新系统该不该选 SM1？** 判断规则很简单——

```text
若业务系统可以接受软件实现/通用密码模块 ──► 选 SM4（公开、快、生态完整、指令加速）
若合规文件明确要求 SM1（存量系统、特定行业） ──► 采购带认证证书的 SM1 硬件产品
新设计的系统没有任何理由主动选择 SM1
```

## 4. SM7：族谱中另一个"存在但不公开"的成员

SM7 在国密算法族谱中的位置与 SM1 相同——**对称分组密码、算法不公开、无国家标准文本**，公开信息极少（业界描述为 128 位分组、128 位密钥）。与 SM1 的差异主要在应用语境：

- SM1 的载体生态（密码卡、密码机、金融数据密码机、VPN 网关）庞大且仍在运行，TLCP 套件表里还留着 SM1 的位置；
- SM7 偶见于**门禁、非接触卡类**方案的算法描述中，从未形成 SM1 那样的产品生态，新系统遇不到独立选型场景；
- 工程处置原则与 SM1 完全一致：见到"SM7"字样时，核验产品认证证书与实际载体，存量按迁移四步走，新系统选 SM4。

## 5. SSF33 等历史算法

早期商密体系中还存在若干非公开或半公开的历史算法：

- **SSF33**：早期分组密码，曾用于部分政务卡类系统与老旧金融设备，规范未公开标准化。存量系统偶尔还能遇到（多见于十年以上的卡片/机具），新系统一律不得选用；
- **SSF02/SSF06 等**：特定行业试点期算法，现均已退出主流。

遇到存量系统使用这些算法时的标准动作：**摸清密钥形态与数据格式 → 规划向 SM4/SM2 的迁移 → 迁移期间做双算法并行兼容 → 下线旧算法**。迁移方案参考第三部分工程实现一章。

## 6. 合规要点

- 采购 SM1（或任何商密）硬件产品时，核验**商用密码产品认证证书**（国家密码管理局官网可查），证书须覆盖所用算法与产品型号；
- 密评项目中，SM1 模块属于"密码产品"，其合规性看认证证书与使用方式（密钥是否在设备内生成/存储/使用），而非算法细节；
- 自行逆向 SM1 并软件实现属于"未经授权实现"，既不合规也无安全价值，不要这么做。
