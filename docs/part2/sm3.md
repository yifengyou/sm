# SM3 密码杂凑算法

SM3 是国密体系的密码杂凑函数（哈希函数），标准为 **GB/T 32905-2016（原 GM/T 0004-2012）**，2018 年进入 ISO/IEC 10118-3 国际标准。它输出 256 位摘要，安全强度 128 位，在整个国密技术栈中无处不在：SM2 签名的 Z 值与摘要、SM2 加密的校验值 C₃、TLCP 的 PRF 与记录层 MAC、KDF 的内部压缩机、HMAC-SM3……可以说**SM3 是国密体系的"胶水算法"**。

## 1. 总体结构

SM3 采用 **Merkle–Damgård 迭代结构**（与 SHA-256 同一设计范式）：

```text
消息 M ──► 填充（与 SHA-256 完全相同）──► 512 位分组 ──► 压缩函数 CF（64 轮）──► 级联
                                                                    │
初始向量 IV ─────────────────────────────────────────────────────────┘
输出：256 位摘要（8 × 32 位寄存器）
```

| 属性 | SM3 | SHA-256（对照） |
| --- | --- | --- |
| 摘要长度 | 256 位 | 256 位 |
| 分组长度 | 512 位 | 512 位 |
| 轮数 | 64 | 64 |
| 字长 | 32 位 | 32 位 |
| 消息扩展 | **68 个扩展字**（W₀…W₆₇ + W′₀…W′₆₃） | 48 个（W…W′，仅加旋转） |
| 布尔函数 | 前后 16 轮**切换**两组 FF/GG | 全轮单一组 |
| 置换函数 | P0/P1（双旋转异或） | Σ/σ 系列 |

SM3 与 SHA-256 最实质的区别有两处：一是消息扩展引入了**非线性函数 P1**（类似消息调度里塞进一个小型"预压缩"），二是布尔函数在**第 15/16 轮切换**，两者都旨在增强扩散、抵抗早期对 MD5/SHA-1 有效的差分攻击。

## 2. 填充规则

与 SHA-256 完全一致：

```text
M  ‖ 0x80  ‖ 00…00  ‖ 64 位大端比特长度
使总长度 ≡ 448 (mod 512)，再补 64 位长度后恰为 512 的整数倍
```

## 3. 常量与记号

```text
IV（8×32 位）：
  7380166F 4914B2B9 172442D7 DA8A0600 A96F30BC 163138AA E38DEE4D B0FB0E4E

轮常量：
  T_j = 0x79CC4519   (0 ≤ j ≤ 15)
  T_j = 0x7A879D8A   (16 ≤ j ≤ 63)
  使用时左循环移 j 位（j mod 32）：即轮内实际参与加法的是 T_j <<< j

布尔函数（j 为轮号）：
  FF_j(X,Y,Z) = X ⊕ Y ⊕ Z                        (0 ≤ j ≤ 15)
  FF_j(X,Y,Z) = (X ∧ Y) ∨ (X ∧ Z) ∨ (Y ∧ Z)      (16 ≤ j ≤ 63)

  GG_j(X,Y,Z) = X ⊕ Y ⊕ Z                        (0 ≤ j ≤ 15)
  GG_j(X,Y,Z) = (X ∧ Y) ∨ (¬X ∧ Z)               (16 ≤ j ≤ 63)

置换函数：
  P0(X) = X ⊕ (X <<< 9) ⊕ (X <<< 17)
  P1(X) = X ⊕ (X <<< 15) ⊕ (X <<< 23)

记号：⊕ 按位异或；∧ ∨ 按位与/或；<<< n 32 位左循环移；+ 模 2³² 加
```

设计注解：GG 后 16 轮的 `(X∧Y)∨(¬X∧Z)` 是**多路选择器**（Z 按 X 逐位选通），与 MD 系列的选择函数同族；FF 后 16 轮则是**多数函数**。布尔函数切换 + T_j 切换在同一个边界（第 16 轮起）发生，这让前后两段的差分特性"错位"，是抗差分攻击的主要设计手段之一。

## 4. 消息扩展

每个 512 位分组 B 被解释为 16 个 32 位大端字 W₀…W₁₅，再扩展出 52 个新字：

```text
for j = 16 … 67:
    W_j = P1( W_{j−16} ⊕ W_{j−9} ⊕ (W_{j−3} <<< 15) ) ⊕ (W_{j−13} <<< 7) ⊕ W_{j−6}

for j = 0 … 63:
    W′_j = W_j ⊕ W_{j+4}
```

理解要点：

- 扩展到 W₆₇（共 68 字）而不是 W₆₃，是因为 W′ 的定义向前借了 4 个字（W′₆₃ 需要 W₆₇）；
- SHA-256 的消息调度是纯线性（异或 + 移位），SM3 在其中嵌入了**非线性 P1**，这使"消息修改"类差分攻击（击垮 MD5/SHA-1 的那类技术）难以直接移植；
- 实现时若内存受限，W 数组可以做成 68 字循环缓冲，W′ 按需现算。

## 5. 压缩函数（64 轮）

状态为 8 个 32 位寄存器 `A B C D E F G H`，每轮：

```text
for j = 0 … 63:
    SS1 = ( (A <<< 12) + E + (T_j <<< j) ) <<< 7
    SS2 = SS1 ⊕ (A <<< 12)
    TT1 = FF_j(A,B,C) + D + SS2 + W′_j
    TT2 = GG_j(E,F,G) + H + SS1  + W_j
    D = C
    C = B <<< 9
    B = A
    A = TT1
    H = G
    G = F <<< 19
    F = E
    E = P0(TT2)

64 轮结束后：V_(i+1) = V_i ⊕ (A B C D E F G H)     # Davies–Meyer 式级联
```

几个容易被实现者写错的细节：

1. **`A <<< 12` 出现两次**（SS1 内与 SS2），必须用同一个值——若两次独立计算且轮中 A 已被更新会出错；正确实现是先算 `A12 = A <<< 12` 再复用；
2. **T_j 的旋转是"按轮号 j"**，不是固定移位；`T_j <<< j` 中 j 需取模 32（j 本身 < 64，故 16 ≤ j < 32 与 32 ≤ j < 64 的移位不同）；
3. **C 与 G 的旋转（9/19）发生在赋值时刻**：`D = C; C = B <<< 9` 的顺序意味着 D 拿到的是**未旋转**的 C；
4. **状态更新是"错位传递"**：`B ← A`、`F ← E` 都取**轮前**的值（F 的新值来自轮前的 E，而非 F 自身）——把 `F ← E` 误写成 F 自传递是真实高发笔误，任何一条标准 KAT 都能立刻拦截；
5. 级联输出是与**轮前**的 V_i 异或（Davies–Meyer 单向化的标准做法）。

## 6. 完整参考实现（Python）

```python
import struct

M32 = 0xFFFFFFFF
def rol(x, n):
    n %= 32
    return ((x << n) | (x >> (32 - n))) & M32 if n else x

IV = [0x7380166F, 0x4914B2B9, 0x172442D7, 0xDA8A0600,
      0xA96F30BC, 0x163138AA, 0xE38DEE4D, 0xB0FB0E4E]

def P0(x): return x ^ rol(x, 9) ^ rol(x, 17)
def P1(x): return x ^ rol(x, 15) ^ rol(x, 23)

def sm3(msg: bytes) -> bytes:
    ml = len(msg) * 8
    msg = msg + b'\x80'
    while len(msg) % 64 != 56:
        msg += b'\x00'
    msg += struct.pack('>Q', ml)

    V = IV[:]
    for off in range(0, len(msg), 64):
        W = list(struct.unpack('>16I', msg[off:off+64]))
        for j in range(16, 68):
            W.append(P1(W[j-16] ^ W[j-9] ^ rol(W[j-3], 15))
                     ^ rol(W[j-13], 7) ^ W[j-6])
        Wp = [W[j] ^ W[j+4] for j in range(64)]

        A, B, C, D, E, F, G, H = V
        for j in range(64):
            T = 0x79CC4519 if j < 16 else 0x7A879D8A
            SS1 = rol((rol(A, 12) + E + rol(T, j)) & M32, 7)
            SS2 = SS1 ^ rol(A, 12)
            FF = (A ^ B ^ C) if j < 16 else ((A & B) | (A & C) | (B & C))
            GG = (E ^ F ^ G) if j < 16 else ((E & F) | ((E ^ M32) & G))
            TT1 = (FF + D + SS2 + Wp[j]) & M32
            TT2 = (GG + H + SS1 + W[j]) & M32
            D, C, B, A = C, rol(B, 9), A, TT1
            H, G, F, E = G, rol(F, 19), E, P0(TT2)
        V = [v ^ x for v, x in zip(V, [A, B, C, D, E, F, G, H])]

    return struct.pack('>8I', *V)
```

（本实现的输出已对照 GB/T 32905 附录 A 测试向量及 OpenSSL 独立实现双重复核。）

## 8. 派生用法

### 8.1 HMAC-SM3

HMAC 的通用构造（RFC 2104）与具体杂凑无关，直接套用：

```text
HMAC-SM3(K, m) = SM3( (K′ ⊕ opad) ‖ SM3( (K′ ⊕ ipad) ‖ m ) )
块长 64 字节，输出 32 字节
```

HMAC-SM3 是 TLCP 记录层的 MAC 与 PRF、以及各类国密协议里 MAC/KBKDF 的基础构件。

### 8.2 KDF

国密体系通用的"SM3 计数器模式 KDF"（见 SM2 章 5.3 节），TLCP 的密钥块、SM9 的会话密钥都由它派生。

### 8.3 口令哈希

SM3 不是口令存储算法（无盐、无慢化）。需要存口令时应使用 PBKDF2/Argon2 等方案并以 HMAC-SM3 作为 PBKDF2 的 PRF（部分合规场景要求这样组合）。

## 9. 安全性分析

- **碰撞（理想 2^128）/ 原像（理想 2^256）**：对完整 64 轮 SM3，公开文献中没有优于通用攻击的结果；
- **简化轮攻击**：公开研究（差分分析、中间相遇、布尔函数简化等路线）目前对约 30+ 轮的简化版 SM3 有理论区分器/碰撞构造，距完整 64 轮尚有充足安全裕度；这也解释了 SM3 为何用 64 轮（结构相似、轮数相同的 SHA-256 面对同类分析的裕度也是这个量级）；
- **长度扩展攻击**：作为 Merkle–Damgård 结构，SM3 与 SHA-256 一样存在长度扩展性质——`H(m)` 泄露时可直接计算 `H(m ‖ pad ‖ suffix)`。**不要裸用 SM3 做 MAC**，应使用 HMAC-SM3。

## 10. 实现与性能

- **软件**：SM3 单分组 64 轮约 200 余条基础指令量级，纯 C 实现吞吐与 SHA-256 同一量级、略慢（循环移位多、消息扩展多一层非线性）；SIMD 优化（AVX2 多分组并行、NEON）可显著提升流式吞吐；
- **硬件**：SM3 的数据通路（加法 + 大量循环移位 + 少量逻辑）硬件成本极低，国产 CPU 的安全引擎、密码卡、HSM 普遍内建 SM3，吞吐可达数 GB/s 量级；
- **零依赖移植**：参考实现约 100 行 C，无查表（SM4 对比鲜明），侧信道面小，适合嵌入式（唯一注意点：轮常量旋转与上述赋值顺序细节）。
