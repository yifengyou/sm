# SM9 标识密码算法

SM9 是国密体系中最具特色的算法——**标识密码（Identity-Based Cryptography, IBC）**：用户的邮箱、手机号、设备 ID 等标识**本身就是公钥**，无需数字证书。标准为 **GB/T 38635-2020（原 GM/T 0044-2016）**，2021 年其数字签名部分进入 ISO/IEC 14888-3 国际标准。

代价与收益同样鲜明：IBC 免掉了证书、CA 与证书链校验的整个复杂度，但引入了**密钥生成中心（KGC）**——它掌握主密钥，可以派生任何用户的私钥（天然的密钥托管模型）。理解这对矛盾，是理解 SM9 全部设计与应用边界的关键。

## 1. 数学基础：双线性对

### 1.1 什么是双线性对

设 G₁、G₂ 是阶为素数 n 的加法循环群（椭圆曲线点群），G_T 是阶为 n 的乘法群。双线性对是满足如下性质的映射 e: G₁ × G₂ → G_T：

```text
双线性： e([a]P, [b]Q) = e(P, Q)^{ab}      对任意整数 a, b
非退化： e(P, Q) ≠ 1（存在 P, Q 使其非单位元）
可计算： e 可在多项式时间算出
```

第一条性质是全部 IBC 构造的引擎：它把两个群里的标量乘"搬"到目标群里变成指数乘积，使"分别持有秘密 a、b 的双方"能在不泄露秘密的前提下对乘积 ab 达成一致——这正是"发送方用标识加密、只有 KGC 派生的私钥才能解出"的数学机制。

### 1.2 SM9 的曲线与配对参数

SM9 采用 **256 位 BN 曲线**（Barreto–Naehrig 曲线），记号与要点：

| 元素 | 说明 |
| --- | --- |
| E(F_p) 上的曲线 | BN 曲线，方程形如 y² = x³ + b（具体参数固定于 GB/T 38635.1） |
| n | 群的阶（256 位素数），G₁、G₂、G_T 的公共阶 |
| G₁ | E(F_p) 上 n 阶子群（基域运算，点运算最快） |
| G₂ | E(F_p²) 上 n 阶子群（经扭曲线 twist 得到，运算最慢） |
| G_T | F_p¹² 中的 n 阶子群（嵌入度 k = 12） |
| e | 基于 BN 曲线的双线性对（Tate/R-ate 类配对） |
| P₁、P₂ | 标准规定的 G₁、G₂ 生成元 |

**嵌入度 k = 12 的含义**：配对把 ECDLP"搬运"到有限域 F_p^k 的乘法群中（MOV 归约）。若 k 太小（如超奇异曲线的 k≤6），子群上的 DLP 就会被域上 index calculus 攻击击穿，安全性崩塌；BN 曲线取 k=12，使 256 位曲线在配对映射下仍保持约 128 位安全强度——**IBC 曲线选型比普通 ECC 苛刻得多**，这是"不能随便拿一条 SM2 曲线做 IBC"的根本原因。

**工程代价**：配对运算是 SM9 所有操作中最贵的构件（软件实现毫秒量级，约为一次 SM2 标量乘的十倍上下），F_p¹² 乘法、扭曲线点运算的实现门槛显著高于普通 ECC。这也解释了 SM9 的软硬生态远薄于 SM2/SM3/SM4。

## 2. 体系结构与密钥派生

### 2.1 角色与主密钥

```text
KGC（密钥生成中心）：
  为"签名"与"加密/密钥交换"分别维护独立主密钥：
    签名主私钥 s ←R [1, n−1]，主公钥 P_pub-s = [s]P₁
    加密主私钥 ke ←R [1, n−1]，主公钥 P_pub-e = [ke]P₂   # 群指派以标准文本为准
  主公钥是全系统公开参数；主私钥是全系统信任之锚
```

### 2.2 用户密钥派生（以标识 ID_B 为例）

```text
1. h_B = H1( ID_B ‖ hid, n )     # H1：SM3 构造的"杂凑到整数"；hid 为区分
                                 # 签名/加密/密钥交换的单字节识别符
2. 边界检查（例如签名密钥要求 h + s ≢ 0 mod n，否则 KGC 须换主密钥）
3. KGC 用主私钥算出用户私钥，经安全信道下发：
     签名私钥 d_B —— 含主私钥的逆元结构（验证方程要求，见下）
     加密私钥 de_B = [ke]·Q_B，其中 Q_B = [h_B]P₁ 为"标识公钥"
4. 任何人都可自行计算 Q_B = [h_B]P₁ —— 标识即公钥，免证书
```

结构解读：

- **标识公钥 Q_B**：任何人用 ID_B + 公开参数即可算出，这就是"免证书"的实现方式；同时它进入所有协议方程，**身份串是被密码学绑定的，不是带外声明**；
- **私钥必须经 KGC**：de_B 的计算需要 ke，用户自己无法生成——所以 KGC 天然知道所有用户私钥（托管）；
- **撤销怎么做**：标准做法是把有效期并入标识（如 `alice@example.com|2030-12-31`），过期后 KGC 不再派发新私钥，旧私钥自然失效——撤销问题转化为密钥派发策略问题。

## 3. 数字签名

SM9 签名输出二元组 **(h, S)**，h 是杂凑值、S 是曲线点。流程（记 g = e(P₁, P₂)，公式按 GB/T 38635.2 的构造，群指派以标准文本为准）：

```text
签名（A，持有 d_A）：
1. r ←R [1, n−1]
2. w = g^r                        # 目标群 GT 中的幂
3. h = H2( M ‖ w, n )             # H2：SM3 构造的"杂凑到整数"
4. l = (r − h) mod n；l = 0 则回到 1
5. S = [l] d_A                    # 签名者私钥点的标量乘
6. 输出 σ = (h, S)

验签（任何验证者）：
1. 校验 h ∈ [1, n−1]，S 是合法群点
2. h_A = H1( ID_A ‖ hid, n )
3. w′ = e( S, P_pub-s + [h_A]P₁ ) · g^h
4. 校验 h = H2( M ‖ w′, n )，相等则通过
```

**正确性**（代数闭环）：设 d_A = [t_A]P₂ 且 t_A·(s + h_A) ≡ 1 (mod n)，则

```text
e(S, P_pub-s + [h_A]P₁) = e([l·t_A]P₂, [s + h_A]P₁) = g^{l·t_A·(s+h_A)} = g^{(r−h)}
再乘 g^h 得 g^{r−h+h} = g^r = w  ✓  于是 H2(M ‖ w′) = h
```

这解释了 2.2 节"签名私钥含逆元结构"的来源：验证方程把主公钥、标识公钥与签名捏在一个配对式里，只有 t_A 取 (s + h_A)⁻¹ 才能闭环。

与 BLS 签名对比：BLS 是 σ = [H(m)]sk 的纯配对等值检查（签名极短）；SM9 引入随机数 r 与杂凑 h，形式上更接近"把 Schnorr 协议搬进 GT"，签名是 (h, 点S) 两元组而非单个点。

## 4. 密钥封装与公钥加密

SM9 定义了密钥封装机制（KEM）与在此基础上组合对称加密（DEM）的公钥加密方案：

```text
封装（发送方 A → 标识 ID_B）：
1. r ←R [1, n−1]
2. R = [r]P₂                     # 封装密文分量（曲线点）
3. w = e( Q_B, P_pub-e )^r = g^{h_B·ke·r}    # Q_B = [h_B]P₁ 为标识公钥
4. K = KDF( R ‖ w, klen )        # SM3 计数器模式 KDF
5. 输出封装 (R, K)，K 用于 DEM（如 SM4-GCM）加密消息

解封（接收方 B，持有 de_B = [ke·h_B]P₁）：
1. w′ = e( de_B, R ) = g^{ke·h_B·r}          # 与发送方的 w 相等
2. K = KDF( R ‖ w′, klen )
```

正确性一目了然：`e(de_B, R) = e([ke·h_B]P₁, [r]P₂) = g^{ke·h_B·r} = w`。而第三方没有 ke，算不出 w——这就是"标识加密"的全部魔法。

注意点：

- 完整的 SM9 加密方案在 KEM+DEM 之上还有**完整性校验分量**（与 SM2 密文的 C₃ 同族思想），防篡改/防选择密文，实现时不可裁剪；
- KEM 的随机数 r 与 SM2 加密的 k 同样"一次一用"，重用会破坏机密性；
- 消息长度基本不受限（DEM 承担数据加密），这一点与 SM2 加密的 KDF 一次一密结构一致。

## 5. 密钥交换

SM9 密钥交换（IBK）允许两个标识用户在 KGC 预先派发私钥的前提下协商会话密钥：双方各出临时随机数与临时曲线点，交换后用**配对值 + 双方标识杂凑**经 KDF 派生会话密钥，并可附加确认值（与 SM2 密钥交换的 S_A/S_B 确认机制同族）。安全性质与适用边界：

- 双方身份通过标识私钥的持有性隐式认证（配对方程闭环即证明对方持有该标识的私钥）；
- 与所有 IBC 一样，**KGC 能冒充任何用户参与协议**（它有全部私钥）——对 KGC 的信任是前提而非结论；
- 高安全等级系统若不能接受托管，应改用 SM2/TLS 的"证书 + (EC)DHE"路线。

## 6. 安全性分析

### 6.1 算法与参数层

- 安全性同时依赖三件事：BN 曲线 ECDLP、F_p¹² 乘法群 DLP（配像搬移后）、以及 KDF/杂凑的 SM3。k=12 的嵌入度是参数安全的命门——SM9 的曲线参数由标准固定，**实现者绝不可自行更换曲线**（低嵌入度或非扭安全曲线会直接击穿体系）；
- 公开分析未发现对完整 SM9 的有效攻击。

### 6.2 体系层（IBC 特有的风险面）

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| **KGC 托管** | 主私钥持有者可派生任何用户私钥、解密任何历史密文、冒充任何人签名 | 主密钥分片/门限化（多 KGC 联合）、托管协议与审计、敏感场景改用 PKI |
| 主密钥泄露 | 灾难级：全系统私钥可重算、历史签名可伪造（若不绑时间） | 硬件保护（HSM）、主密钥备份的物理安全、标识含有效期限定爆炸半径 |
| 私钥分发信道 | 私钥经 KGC→用户的通道下发，通道被截即失守 | 离线发key仪式/加密下发+口令封装（如 PBE） |
| 撤销与有效期 | 无 CRL/OCSP 对应物，撤销靠"标识里带有效期+停止派发" | 派发策略系统化、短周期标识 |

### 6.3 实现层

- **公钥/私钥点校验**：配对函数对"不在正确子群里的点"可能仍给出结果，必须先验证点在正确 n 阶子群（防无效曲线/小子群攻击）；
- **配对实现侧信道**：配对是长而复杂的多项式求值链，时序/功耗泄漏面大，高价值场景用常数时间实现或硬件；
- 兼容性：G₂/F_p¹² 运算实现细节多（塔式扩域、扭曲线坐标），跨库联调前先对跑标准 KAT。

## 7. 性能画像（数量级）

| 操作 | 主要开销 | 相对量级（软实现） |
| --- | --- | --- |
| 用户私钥生成（KGC） | 1 次逆元 + 1 次标量乘 | ≈ SM2 一次签名 |
| 签名 | 1 次 GT 指数 + 1 次标量乘 | ≈ 10× SM2 签名 |
| 验签 | 1 次配对 + 1 次 GT 指数 | ≈ 10× SM2 验签 |
| 封装/解封 | 1 次配对（或 1 次 GT 指数） | ≈ 10× SM2 加密 |

结论：SM9 是"用计算换证书体系"的算法——省掉 PKI 的证书签发、分发、链校验、撤销基础设施，付出每次操作约一个数量级的公钥运算开销。大批量高频场景（每笔交易都验签）对成本敏感时，SM2+证书往往更划算。

## 8. 应用场景与生态

| 场景 | 为什么适合 SM9 |
| --- | --- |
| 物联网/设备标识加密 | 设备出厂无证书负担，用设备 ID 直接加密下发指令/密钥 |
| 邮件/文档标识加密 | 收件人邮箱即公钥，无需先拿到对方证书 |
| 通信标识（手机号）安全 | 号码即标识，电信场景天然匹配 |
| 区块链标识密钥 | 账户地址/链上 DID 即标识，KGC 可由联盟共治（门限主密钥） |
| 电子印章/签章系统 | 印章标识绑定签发主体，简化证书链 |

实现生态：BouncyCastle（SM9 全套）、GmSSL、Tongsuo 等均提供 SM9；硬件层面支持 SM9 的密码卡/密码机少于 SM2/SM4，选型时需专项确认（合规项目中还应确认产品认证证书覆盖 SM9）。

## 9. SM9 vs PKI（SM2）选型对照

| 维度 | SM9（IBC） | SM2 + 证书（PKI） |
| --- | --- | --- |
| 公钥获取 | 标识即可（零基础设施） | 需证书分发与链校验 |
| 信任模型 | KGC 全知（托管） | CA 只证明公钥归属（不知私钥） |
| 撤销 | 派发策略 + 有效期进标识 | CRL/OCSP 成熟机制 |
| 性能 | 配对昂贵（~10×） | 普通 ECC |
| 合规成熟度 | 场景化使用 | 主流通用方案 |
| 典型选择 | 海量弱设备、标识天然存在的封闭体系 | 开放互联网、高安全等级系统 |
