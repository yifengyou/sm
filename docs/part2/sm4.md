# SM4 分组密码算法

SM4 是国密体系的分组密码，标准为 **GB/T 32907-2016（原 GM/T 0002-2012）**，2021 年纳入 ISO/IEC 18033-3 国际标准。分组与密钥均为 **128 位**，迭代 **32 轮**，是 TLCP 记录层、VPN、文件与数据库加密、物联网安全芯片中的主力对称算法。

## 1. 总体结构：32 轮平衡 Feistel

```text
明文 (X₀, X₁, X₂, X₃)  ── 每个字 32 位大端 ──┐
                                            │
   ┌──────────────── 32 轮迭代 ───────────────┴───────────────┐
   │                                                          │
   │    X_{i+4} = X_i ⊕ T( X_{i+1} ⊕ X_{i+2} ⊕ X_{i+3} ⊕ rk_i )│
   │                                                          │
   └──────────────────────────────────────────────────────────┘
输出 (Y₀, Y₁, Y₂, Y₃) = (X₃₅, X₃₄, X₃₃, X₃₂)   # 注意逆序输出
```

与 AES 的 SPN 结构不同，SM4 是**平衡 Feistel 网络**（每轮只改一个字，另三个字直通）。这带来三个工程特性：

- 轮函数无需可逆（解密与加密用同一个 T，只是轮密钥逆序）；
- 每轮扩散较慢，故轮数取 32（AES-128 是 10 轮）；
- 数据通路窄（每轮实质处理 1 个 32 位字），硬件面积小、嵌入式友好。

## 2. 轮函数与 T 变换

```text
T(·) = L( τ(·) )

τ（非线性变换）：对 32 位输入的 4 个字节分别查 S 盒
L（线性扩散）  ：L(B) = B ⊕ (B <<< 2) ⊕ (B <<< 10) ⊕ (B <<< 18) ⊕ (B <<< 24)
```

τ 提供混淆（confusion），L 提供扩散（diffusion）——经典 SPN 组件被"塞进"了 Feistel 轮函数。L 的循环移位量（2/10/18/24）设计使单个输入比特在一轮后影响约 2⁵ 个输出位，32 轮后达到完全扩散（实际 8~10 轮即达 avalanche 指标）。

查表方式：输入字节的高 4 位为行、低 4 位为列。例如 S(0x00) = 0xD6，S(0x01) = 0x90，S(0xFF) = 0x48。

S 盒的代数性质：公开研究表明 SM4 S 盒与 GF(2⁸) 上幂函数（逆函数类）仿射等价，与 AES S 盒属于同一代数族；其差分均匀度与非线性度等密码学指标与 AES S 盒相当（差分均匀度 8、非线性度 112 量级），足以抵抗差分与线性密码分析。

## 4. 密钥扩展

128 位密钥同样按 4 个 32 位字处理，用与轮函数同族但线性变换不同的 T′ 生成 32 个轮密钥：

```text
FK = ( A3B1BAC6, 56AA3350, 677D9197, B27022DC )

(K₀, K₁, K₂, K₃) = (MK₀ ⊕ FK₀, MK₁ ⊕ FK₁, MK₂ ⊕ FK₂, MK₃ ⊕ FK₃)

for i = 0 … 31:
    rk_i = K_{i+4} = K_i ⊕ T′( K_{i+1} ⊕ K_{i+2} ⊕ K_{i+3} ⊕ CK_i )

其中 T′(x) = L′(τ(x))，L′(B) = B ⊕ (B <<< 13) ⊕ (B <<< 23)   # 线性部分与 L 不同
```

**CK 常数**（32 个）有简洁的生成规则：`ck_{i,j} = (4i + j) × 7 mod 256`（i 为常数序号 0..31，j 为字节序号 0..3）：

```text
00070E15  1C232A31  383F464D  545B6269     70777E85  8C939AA1  A8AFB6BD  C4CBD2D9
E0E7EEF5  FC030A11  181F262D  343B4249     50575E65  6C737A81  888F969D  A4ABB2B9
C0C7CED5  DCE3EAF1  F8FF060D  141B2229     30373E45  4C535A61  686F767D  848B9299
A0A7AEB5  BCC3CAD1  D8DFE6ED  F4FB0209     10171E25  2C333A41  484F565D  646B7279
```

**解密 = 加密 + 轮密钥逆序**（Feistel 结构的标准红利）：`rk′_i = rk_{31−i}`，轮函数一字不改。

## 5. 参考实现（Python）

```python
import struct
M32 = 0xFFFFFFFF
def rol(x, n): return ((x << n) | (x >> (32 - n))) & M32

SBOX = bytes.fromhex(                        # 256 字节，与第 3 节表格逐行一致
    "d690e9fecce13db716b614c228fb2c05"
    "2b679a762abe04c3aa44132649860699"
    "9c4250f491ef987a33540b43edcfac62"
    "e4b31ca9c908e89580df94fa758f3fa6"
    "4707a7fcf37317ba83593c19e6854fa8"
    "686b81b27164da8bf8eb0f4b70569d35"
    "1e240e5e6358d1a225227c3b01217887"
    "d40046579fd327524c3602e7a0c4c89e"
    "eabf8ad240c738b5a3f7f2cef96115a1"
    "e0ae5da49b341a55ad933230f58cb1e3"
    "1df6e22e8266ca60c02923ab0d534e6f"
    "d5db3745defd8e2f03ff6a726d6c5b51"
    "8d1baf92bbddbc7f11d95c411f105ad8"
    "0ac13188a5cd7bbd2d74d012b8e5b4b0"
    "8969974a0c96777e65b9f109c56ec684"
    "18f07dec3adc4d2079ee5f3ed7cb3948")
FK = [0xA3B1BAC6, 0x56AA3350, 0x677D9197, 0xB27022DC]

def tau(x):
    return (SBOX[x >> 24] << 24) | (SBOX[(x >> 16) & 0xFF] << 16) | \
           (SBOX[(x >> 8) & 0xFF] << 8) | SBOX[x & 0xFF]

def L(b):  return b ^ rol(b, 2) ^ rol(b, 10) ^ rol(b, 18) ^ rol(b, 24)
def Lp(b): return b ^ rol(b, 13) ^ rol(b, 23)
def CK(i): return sum(((4*i + j) * 7 % 256) << (24 - 8*j) for j in range(4))

def key_schedule(mk):
    K = list(struct.unpack('>4I', mk))
    K = [K[i] ^ FK[i] for i in range(4)]
    rk = []
    for i in range(32):
        rk.append(K[i] ^ Lp(tau(K[i+1] ^ K[i+2] ^ K[i+3] ^ CK(i))))
        K.append(rk[-1])
    return rk

def crypt(block, rk):           # 加解密同体；解密传 rk[::-1]
    X = list(struct.unpack('>4I', block))
    for i in range(32):
        X.append(X[i] ^ L(tau(X[i+1] ^ X[i+2] ^ X[i+3] ^ rk[i])))
    return struct.pack('>4I', X[35], X[34], X[33], X[32])
```

## 7. 工作模式

SM4 是分组原语，实际使用必须套工作模式：

| 模式 | 特性 | 国密使用场景 |
| --- | --- | --- |
| ECB | 无 IV、分组独立 | **仅限单分组（如密钥包裹），禁止用于多分组数据** |
| CBC | 需随机 IV，MAC-then-encrypt | TLCP CBC 套件、文件加密（历史存量最大） |
| CTR | 流式、可并行、随机访问 | VPN、高性能通道 |
| GCM | AEAD（加密+认证一体），需唯一 nonce | TLCP GCM 套件、TLS 1.3 国密套件（RFC 8998） |
| CCM | AEAD，适合受限硬件 | 物联网、IoT 芯片 |
| XTS | 数据存储加密 | 磁盘/数据库加密（OpenSSL 3.2+ 提供 SM4-XTS） |

工程纪律：

- **GCM 的 nonce 绝不可重用**（同 key+nonce 重用即泄露认证密钥并破坏机密性），推荐 96 位随机 nonce 或 64 位计数器 + 32 位随机盐；
- CBC 套件继承了 TLS 1.2 时代的填充预言面，新系统优先 GCM/CCM；
- 每密钥加密量遵循 NIST SP 800-38 系列建议（GCM 单密钥建议不超过约 2³² 分组）。

## 8. 安全性分析

- **完整 32 轮**：无实际可行的差分/线性攻击；公开研究的最好结果（差分/线性/中间相遇等路线）约可攻击到 23 轮左右，距离 32 轮有约四分之一的安全冗余——对 128 位分组密码而言裕度健康；
- **密钥扩展**：与 AES 直接使用轮常量加法不同，SM4 的轮密钥经过完整 T′ 变换（含 S 盒），相关密钥类攻击面更小；
- **实现攻击**：查表实现存在缓存时序侧信道（与 AES 查表实现同类），高价值场景应使用指令加速、bitslicing 或掩码实现。

## 9. 实现与性能

### 9.1 查表法

把 `L(τ(x))` 预计算成 4 张 32 位表（每字节一张，T[i] = L(S[i] 移到对应字节位)），一轮变成 4 次查表 + 4 次异或——这是 C 库（GmSSL/OpenSSL）的标准做法，代价是 4KB 常量表。CBC/CTR 模式还可做字节级并行预白化。

### 9.2 指令级加速

- **国产 CPU**：鲲鹏、龙芯、海光等平台在安全引擎或指令层面提供 SM3/SM4 加速，吞吐可达 GB/s 量级，这是国密栈相对国际栈"扳回一城"的地方；
- **AVX2/AVX-512 bitslicing**：把 SM4 按 bitsliced 数据通路重排，一个 AVX2 寄存器并行处理 8/16 个分组，x86 上可逼近 AES-NI 的一半量级，开源实现（如 Tongsuo 的优化路径）已有落地；
- 无加速指令时，SM4 软件性能典型为 AES 的 1/3 ~ 1/5（32 轮查表 vs 10 轮指令），**做国密改造的性能预算时先把 SM4 吞吐测出来**。

### 9.3 硬件与白盒

- 面向嵌入式：Feistel 窄通路 + 单 S 盒复用，SM4 核的面积/功耗优于 AES 核，物联网安全芯片（SE）普遍内置；
- 白盒密码：SM4 白盒实现（查表混淆型）在金融 App、DRM 中大量使用，但公开白盒方案在动态分析下的存活周期有限，白盒只能延缓而非消除密钥提取，关键密钥仍应放服务端或 SE。

### 9.4 白盒 SM4：展开讲（金融 App 的现实选项）

白盒（white-box）威胁模型：攻击者**完全控制运行环境**——能调试进程、dump 内存、插桩每条指令。目标是在这种环境里"藏住"密钥。主流构造思路（Chow 型白盒的 SM4 版）：

```text
把"轮密钥 + 轮函数"整体编译成巨大的查找表网络：
  · 每一轮的 S 盒与轮密钥异或被"吸收"进随机化的表（表 = 随机仿射变换 ∘ 加密逻辑 ∘ 逆仿射变换）
  · 表与表之间靠"内部编码"（internal encoding）串联，中间值从不以明文形式出现在内存
  · 32 轮 SM4 展开后表体积典型为数百 KB ~ 数 MB，密钥"以表的形式存在"，无独立密钥字节可 dump
  · 通常再叠加混淆层：虚指令、表分裂、动态重加密（防静态分析和自动化 DFA）
```

工程认知四条：

- **白盒是"提高提取成本"，不是"不可提取"**：学术界对 Chow 型构造的通用攻击（BGE 类、DFA 故障注入）已较成熟，商业方案靠私有混淆 + 短生命周期对抗——**密钥/表要有轮换机制**（一次一密会话密钥进白盒、长期密钥在服务端的分层用法是金融 App 的主流架构）；
- **合规口径**：白盒属于实现技术而非算法变更（对外仍是标准 SM4），但密评/风控会关注"密钥不出安全边界"的论证——白盒方案通常与协同签名（见密钥管理章）或密钥更新协议配套出现；
- **体积与性能代价**：表展开使白盒 SM4 比查表实现慢 2~10 倍、体积大数个量级，只适合包会话密钥的薄层用途，不适合大批量数据加密；
- **选型现实**：多数商用白盒 SDK 以"加固产品"形态交付（配合检测 Root/调试器/注入的运行时防护），自研白盒不建议——公开构造的攻击工具链很成熟。
