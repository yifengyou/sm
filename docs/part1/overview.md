# 国密概述与发展历程

## 1. 什么是"国密"

"国密"是中国**商用密码**（Commercial Cryptography）体系中密码算法的俗称。《中华人民共和国密码法》（2020 年 1 月 1 日施行）将密码分为三类：

| 类别 | 用途 | 管理主体 |
| --- | --- | --- |
| 核心密码 | 保护国家绝密级、机密级、秘密级信息 | 国家密码管理局 |
| 普通密码 | 保护国家秘密信息 | 国家密码管理局 |
| **商用密码** | **保护不属于国家秘密的信息**（金融、政务、电信、工业控制等） | 国家密码管理局 + 全社会应用 |

"SM 系列算法"（SM2/SM3/SM4/SM9 等）就是商用密码算法的核心组成，SM 即"商密"拼音首字母。需要注意两点：

- **国密 ≠ 国产密码产品**。算法之外，商用密码体系还包括密码产品认证、密评等制度，本手册第四部分展开。
- **国密算法与国际算法是"平行关系"而非"私有关系"**。除 SM1 等少数算法外，SM2/SM3/SM4/SM9/ZUC 的规范全部公开，且多数已进入 ISO/IEC 与 3GPP 国际标准，任何人都可以实现。

## 2. 算法族谱

| 算法 | 类别 | 分组/输出规模 | 密钥长度 | 安全强度 | 是否公开 | 对应国际算法 |
| --- | --- | --- | --- | --- | --- | --- |
| SM1 | 对称分组密码 | 128 位分组（推测） | 128 位（推测） | 128 位 | **不公开**，仅硬件实现 | AES-128（定位） |
| SM2 | 椭圆曲线公钥密码 | 256 位曲线（sm2p256v1） | 256 位私钥 | 128 位 | 公开 | ECDSA / ECDH / ECIES |
| SM3 | 密码杂凑 | 256 位输出 | — | 128 位 | 公开 | SHA-256 |
| SM4 | 对称分组密码 | 128 位分组 | 128 位 | 128 位 | 公开 | AES-128 |
| SM7 | 对称分组密码 | 128 位分组（业界描述） | 128 位（业界描述） | — | **不公开** | AES-128（定位） |
| SM9 | 标识密码（IBC） | 256 位 BN 曲线 + 双线性对 | 主密钥 256 位 | 128 位 | 公开 | Boneh–Franklin IBE / BLS 签名（定位） |
| ZUC（祖冲之） | 序列密码 | 32 位密钥字 | 128 位 + 128 位 IV | 128 位 | 公开 | SNOW 3G（定位） |

几点说明：

- **SM2 是一个"算法族"而非单一算法**：GB/T 32918 系列包含数字签名（Part 2）、密钥交换（Part 3）、公钥加密（Part 4）和参数定义（Part 5），分别对应 ECDSA、ECDH/ECDHE、ECIES 三类国际机制。
- **SM9 的本质是"免证书公钥密码"**：公钥直接由用户标识（如邮箱、手机号、设备 ID）派生，不需要数字证书，代价是引入密钥生成中心（KGC）和私钥托管。
- **ZUC 的主战场是移动通信**：作为 3GPP LTE 的第三套保密性/完整性算法（128-EEA3/128-EIA3），与 SNOW 3G、AES 并列，面向中国市场的 5G/4G 基带与核心网设备大量使用。
- **SM7 是族谱中另一个"存在但不公开"的成员**（与 SM1 同类）：偶见于门禁/非接触卡方案的算法描述里，无公开标准文本、无独立选型场景，工程处置原则与 SM1 相同（见 SM1 章）。
- 所有公开算法的安全强度都按 **128 位**设计，与 AES-128 / SHA-256 / P-256 处于同一安全级别。

## 3. 发展时间线

```text
2007        SM1 随"安全芯片"体系出现（算法保密，仅硬件交付）
2010.12     国家密码管理局公告 SM2 椭圆曲线公钥密码算法及推荐曲线参数
2011.09     ZUC 成为 3GPP LTE 第三套安全算法（128-EEA3 / 128-EIA3，TS 35.221）
2012.03     SM2 / SM3 / SM4 / ZUC 以密码行业标准发布（GM/T 0003 / 0004 / 0002 / 0001）
2012–2014   接口与产品标准密集出台：GM/T 0006（OID）、0010/0015（证书与语法）、
            0016/0018/0019（设备接口）、0022/0024（IPSec/SSL VPN）、0028（密码模块）
2016        SM2/SM3/SM4 升格国家标准：GB/T 32918、GB/T 32905、GB/T 32907；
            ZUC 算法描述升格 GB/T 33133.1（保密性/完整性后升 33133.2/.3-2021）
2016        SM9 发布为 GM/T 0044-2016
2018        GM/T 0054-2018《传输层密码协议（TLCP）》发布，统一国密 SSL 双证书协议
2018        SM2 签名进入 ISO/IEC 14888-3；SM3 进入 ISO/IEC 10118-3；
            ZUC 纳入 ISO/IEC 18033-4（流密码国际标准补篇）
2019.10.26  《密码法》通过（2020.1.1 施行）——密码应用进入依法治理阶段
2020        SM9 升格 GB/T 38635；TLCP 升格 GB/T 38636
2021        SM4 纳入 ISO/IEC 18033-3；SM9 签名纳入 ISO/IEC 14888-3；
            RFC 8998 发布（TLS 1.3 使用 SM2/SM3/SM4）；GB/T 39786-2021 实施（密评依据）
2023.07     修订后《商用密码管理条例》施行（与密码法配套，密评与认证制度细化）
2023–2024   行标密集修订潮：GM/T 0015/0016/0018/0019/0022/0024 等 2023 版发布
            （2024-06-01 起旧版废止）；密评国标化（GB/T 43206-2023 测评要求）
2024–2025   密码模块标准换代（GM/T 0028-2024/0039-2024，2025-07-01 废止旧版）；
            GM/T 0001.4-2024（ZUC AEAD：GXM/MUR）；
            2025 第 54 号公告 20 项行标（含 SM9 行标修订为 GM/T 0044.1~.5-2025、
            协同签名 GM/T 0144/0145-2025，均 2026-07-01 实施）
2026        密评配套国标陆续实施（GB/T 46795/46798-2025，2026-07-01）；
            GB/T 33560-2026（密码应用标识）、GB/T 35275-2026（SM2 消息格式）
            发布——国标侧也进入快速迭代期
```

从这条时间线可以读出国密标准化的两条主线：

1. **"行标 → 国标 → 国际标准"的爬梯路径**：算法先以 GM/T 行标形式公开和试错，稳定后升格 GB/T 国标，再由国内团队推动进入 ISO/IEC。
2. **"算法 → 接口 → 协议 → 评估"的生态闭环**：只有算法无法形成产业，接口规范（SDF/SKF）、协议规范（TLCP、SSL/IPSec VPN）、产品规范（密码卡、密码机、密码模块）与评估制度（检测认证、密评）共同构成可落地的体系。

## 4. 与国际算法的对照

把国密算法放进读者熟悉的国际坐标系里，是最快的理解路径：

| 能力 | 国际体系 | 国密体系 | 关键差异 |
| --- | --- | --- | --- |
| 签名 | ECDSA（P-256）+ SHA-256 | SM2 签名 + SM3 | SM2 把"用户身份 + 曲线参数"预杂凑进消息摘要（Z 值），见第二部分 SM2 章 |
| 密钥协商 | ECDH / ECDHE | SM2 密钥交换 | SM2 协议内建双方身份确认，无需额外签名即可防中间人（静态密钥场景） |
| 公钥加密 | ECIES / RSA-OAEP | SM2 加密 | 密文内建校验值 C3（哈希），抗主动攻击的步骤在协议层而非组合层 |
| 杂凑 | SHA-256 / SHA-3 | SM3 | 结构同为 Merkle–Damgård，但 SM3 的消息扩展更复杂（68 个扩展字） |
| 对称加密 | AES-128（10 轮） | SM4（32 轮） | SM4 轮数多但每轮轻，无公开的指令级加速前，软件性能普遍低于 AES-NI |
| 流密码 | SNOW 3G / AES-CTR | ZUC | ZUC 的 LFSR 建在素域 GF(2^31−1) 上（模加），SNOW 3G 建在 GF(2^32) 扩域上（模乘） |
| 身份密码 | （无主流标准化对应） | SM9 | 国际上 IBE 一直没有大规模标准化部署，SM9 是少数进入国标的 IBC 体系 |
| 传输安全 | TLS 1.2 / 1.3 | TLCP（GB/T 38636）/ TLS 1.3 + RFC 8998 | TLCP 采用"双证书"（签名 + 加密）制度，是最具国密特色的设计 |

## 5. 为什么要建一套自己的算法体系

抛开非技术因素，纯从密码工程角度，国密体系的技术价值至少有四点：

1. **密码多样性（crypto-agility）**。单一算法族（如 AES+SHA+RSA/ECDSA）一旦出现结构性攻击或量子威胁，整个生态需要迁移。提前建设并维护第二套经过完整标准化的算法族，是降低"全军覆没"风险的工程手段。国密体系普遍支持"双算法并行、按套件协商"的部署形态，本身就是密码敏捷性的实践。
2. **供应链自主**。密码模块是最底层的安全依赖。HSM、密码卡、安全芯片、VPN 网关如果全部依赖境外 IP，在断供场景下无法替换。
3. **全栈一致性**。从 CPU 指令（国产处理器普遍内建 SM3/SM4 加速）、操作系统密码库、TLS 协议栈到浏览器，国密有端到端的技术栈闭环，性能优化可以做得很深。
4. **场景创新**。SM9 这类标识密码体系在国际标准化中推进缓慢，国密率先在物联网、标识解析、区块链等"以标识为中心"的场景中完成了标准化和商用，这类"标识即公钥"的部署模式在传统 PKI 下成本很高。

## 6. 安全性总评

- **设计来源**：SM2/SM3/SM4/ZUC/SM9 均由国内专业密码机构设计，公开接受学术界分析十余年。截至目前，**所有公开算法的完整轮数/完整参数下均无实际可行（低于穷举复杂度量级）的攻击**，128 位安全强度仍然成立。
- **已知分析边界**（详见各算法章节）：SM3 的最优碰撞类攻击可穿透约半数轮数（32/64 轮级别）的简化版本；SM4 的差分/线性分析最多到达约 23/32 轮；SM2 的安全性归约到 sm2p256v1 曲线上的 ECDLP，与 P-256 同级；SM9 的安全性依赖 BN 曲线配对参数与双线性对实现细节。
- **真正的风险在工程层**：SM2 签名随机数重用/泄露导致的私钥恢复（与 ECDSA 同病）、SM4-CBC 的填充预言（与 TLS 1.2 同病）、SM9 的 KGC 托管与撤销问题、以及 TLCP 双证书体系的前向保密缺口——这些"用法病"远比"算法病"常见，本手册会在对应章节逐一展开。
