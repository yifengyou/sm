# 商用密码应用安全性评估（密评）

密评是国密体系的"验收环节"：由具备资质的测评机构，依据国家标准对信息系统**密码应用的合规性、正确性、有效性**进行评估。本章面向被测评方（建设方/运营方）视角展开。

## 1. 法律依据与触发条件

| 依据 | 要点 |
| --- | --- |
| 《密码法》第二十七条 | 法律法规要求使用商密保护的**关键信息基础设施**，运营者应当使用商密保护，并自行或委托检测机构开展商密应用安全性评估 |
| 《商用密码管理条例》（2023 修订） | 细化密评制度；**关基运营者每年至少开展一次密评**；检测/测评机构实行名录管理 |
| GB/T 39786-2021 | 《信息安全技术 信息系统密码应用基本要求》——密评的技术标尺 |
| 等保 2.0 | 定级为**第三级及以上**的信息系统，同步要求使用商密保护并接受密评 |

实操判断：

```text
系统定级等保三级及以上 ─┐
系统属于关基            ─┼──► 依法应当使用商密保护 + 定期密评（关基每年≥1次）
行业主管有明确密评要求  ─┘      （金融、政务、医疗等行业另有细化文件）
其余系统：鼓励参照执行；密评结论常被用作投标/行业准入的加分或门槛项
```

## 2. GB/T 39786-2021 框架

```text
信息系统密码应用基本要求
│
├── 总体要求：算法、技术、产品、服务四方面合规（用商密算法、经认证的密码产品）
│
├── 技术要求（四个层面 × 逐级增强的一~四级要求）
│   ├── 物理和环境安全：门禁/视频的密码保护、电子门禁记录完整性
│   ├── 网络和通信安全：通信实体身份鉴别、传输机密性/完整性（↔ TLCP/VPN）
│   ├── 设备和计算安全：设备准入鉴别、远程管理通道加密、日志记录完整性
│   └── 应用和数据安全：用户身份鉴别、重要数据传输/存储的机密性与完整性、
│                        抗抵赖（数字签名/可信时间戳）
│
└── 管理要求
    ├── 管理制度：密钥管理全生命周期制度文件（制定/发布/修订）
    ├── 人员管理：岗位、技能培训、考核、保密协议
    ├── 实施运行：规划/建设/运行各阶段的密码应用落实
    └── 应急处置：密码方案/密钥安全的应急预案与演练
```

等级差异的核心逻辑（示意，具体以标准文本为准）：

- **第一/二级**：要求覆盖面递增，允许"重要数据传输加密"等采取基础措施；
- **第三级**（密评主力档）：随机数必须使用合规随机源、密钥全生命周期管理、传输与重要数据存储全面商密保护、密码产品需持证；
- **第四级**：在三級基础上增加更严格的密钥管理制度（如密钥分段管理、更高等级密码模块）、抗抵赖等强化项。

配套的测评实施标准（GM/T 0115《信息系统密码应用测评要求》、GM/T 0116《信息系统密码应用测评过程指南》）把上述要求翻译成可打分的测评活动与判定准则。

### 2.1 测评单元与量化判定

GB/T 39786 的每条要求在测评中被拆解为可独立判定的**测评单元**，每个单元基于"访谈 + 核查 + 测试"三类证据判定：

| 单元判定 | 含义 |
| --- | --- |
| 符合 | 证据完整，满足要求的全部要素 |
| 部分符合 | 满足主要要素，缺陷不影响该要求的整体有效性 |
| 不符合 | 关键要素缺失或失效 |
| 不适用 | 要求与系统客观不相关（须给出正当理由并记入报告） |

- 总体结论由**量化得分 + 风险分析**共同决定：单元判定按 GM/T 0116 的规则折算汇总，同时叠加风险等级分析——高风险项（如密钥明文存储、随机数全量不合规）对结论有实质性压低作用。具体折算方式与阈值以现行 GM/T 0115/0116 及密评联委会发布的细则为准，准备材料时切勿按旧版文件或传闻口径"应试"；
- **"不适用"是评审退回高发区**：标注不适用必须给出系统边界或业务上的正当理由，乱标不适用会被整体复核。

## 3. 密评的两种形态与流程

| 形态 | 时机 | 产出 |
| --- | --- | --- |
| **方案评估**（密码应用方案评估） | 规划/建设阶段 | 对《密码应用方案》的评估意见——先审方案再建设，避免建成即不合规 |
| **系统测评**（运行密评） | 系统建成运行后；关基每年至少一次 | 测评报告，结论：**符合 / 基本符合 / 不符合** |

系统测评的典型流程：

```text
1 准备：材料自备（系统定级报告、密码应用方案、密码产品清单及认证证书、
        密钥管理制度、网络拓扑、数据流图）
2 现场测评：访谈、核查（文档/配置）、技术验证（抓包验证传输加密、
        检查密钥存储、随机数来源、验签逻辑实测）、工具测试
3 风险分析与量化判定：逐测评项给出符合/部分符合/不符合
4 报告与结论：出具报告；按规定报送（关基/重要领域系统）
5 整改复测（如有）
```

准备阶段材料清单（缺项即测评延期）：

| 材料 | 要点 |
| --- | --- |
| 系统定级/备案证明 | 确定等保级别，据此确定密评目标等级 |
| 密码应用方案（及方案评估意见） | 未做过方案评估的先补差距分析 |
| 密码产品清单与认证证书 | 型号/数量/证书有效期逐项对应 |
| 密钥管理制度与台账 | 覆盖生成→销毁全生命周期的记录 |
| 网络拓扑与数据流图 | 标注每个密码保护点（通道/存储/鉴别/抗抵赖） |
| 关键配置与调用链证据 | 随机数来源、密钥存储、验签逻辑（配置截图/代码） |

## 4. 常见不合格项 TOP 清单（按出现频率）

| # | 不合格项 | 典型场景 | 整改方向 |
| --- | --- | --- | --- |
| 1 | **随机数不合规** | 应用直接读 `/dev/urandom`、自研 PRNG 生成密钥/IV | 换用符合 GM/T 0105 的软件随机源或密码设备随机数接口 |
| 2 | **传输未用商密** | 内网服务明文 HTTP；用国际 TLS 充数 | 部署 TLCP/RFC 8998 网关，通道全覆盖 |
| 3 | **算法不合规** | 用 AES/RSA/SHA-256 实现全部密码功能；或"SM4"是自研未认证实现 | 换持证密码产品或合规密码库+密码模块 |
| 4 | **密码产品无认证证书** | 使用未列入认证目录的设备/超范围使用 | 采购时核验商用密码产品认证证书（官网可查） |
| 5 | **密钥明文存储** | 密钥写死在代码/配置文件；证书私钥落盘无保护 | HSM/加密卡托管，或密钥加密存储+分级管理 |
| 6 | **数据存储未加密/未校验完整性** | 数据库明文存敏感字段；日志可被篡改 | SM4 存储加密、HMAC-SM3/SM3 链式完整性 |
| 7 | **密钥管理制度缺失** | 无密钥生成/分发/更换/销毁/备份恢复的成文制度与记录 | 补制度+落台账+演练留痕 |
| 8 | **身份鉴别未用商密** | 登录口令弱哈希、无抗抵赖 | SM2 数字签名/证书认证、可信时间戳 |
| 9 | 时间戳不可信 | 自建 `time()` 取时间做"时间戳" | 接入可信时间戳服务（签名+时间源合规） |

> 经验规律：密评不合格的重灾区几乎全在**工程与管理制度**，而非算法本身——"用了国密"和"用对了国密"之间隔着一整套密钥管理与产品合规。

## 5. 整改与复测

```text
测评报告 ─► 整改计划（逐项对应不符合/部分符合项，定责定期）
        ─► 技术项与管理项并行整改
        ─► 整改证据归档（配置/代码 diff、制度文件、台账记录）
        ─► 复测（定向复核 or 全量，由测评机构按整改影响面确定）
        ─► 结论更新与报送
```

- **技术项优先级**与 TOP 清单同序：随机数 → 密钥存储/托管 → 传输通道 → 存储加密与完整性；
- **管理项（制度/台账）**整改成本最低、见效最快，务必与技术项并行推进，而非等技术改完再补文档；
- **复测范围**：仅改配置/参数的通常定向复核；动了密码产品选型或部署拓扑的按全量处理；
- **根因修复优先**：密评按年度节奏重复发生，同样的缺陷下一轮还会被查——"制度 + 工具化"的根因修复远比点状修补划算。

## 6. 密评与等保、关基的协同

```text
等保定级（三级+）──► 依法使用商密 ──► 按 GB/T 39786 建设 ──► 密评
      │                                                        │
      └────────── 测评时间/机构/材料 通常统筹安排，一次进场两评协同 ──┘
```

- 等保测"安全措施有没有"，密评测"密码措施是否合规、正确、有效"——两者对象重叠、视角互补；
- 关基运营者：密评每年至少一次，结论与整改情况是监管检查的重点；
- 方案先行：新建三级+系统建议在规划阶段就做密码应用方案评估，比建成整改便宜一个数量级。

## 7. 给建设方的行动清单

**系统还没建**：

1. 立项即引入密码应用需求（对照 GB/T 39786 选定目标等级）；
2. 设计《密码应用方案》：算法选型、密钥管理体系、产品清单（先查认证目录）、部署拓扑；
3. 方案评估 → 按方案建设 → 竣工测评。

**系统已建成**：

1. 自查表过一遍第 4 节 TOP 清单（多数问题一天内可初判）；
2. 先做"低垂果实"整改：随机数、密钥托管、传输加密通常改动小见效快；
3. 委托测评机构预评/正式测评，按报告整改；
4. 把密钥管理制度与台账补齐——制度项整改成本最低但最容易被忽略。

**持续运营**：

- 建立密钥管理台账与年度自查；
- 密码产品证书有效期与产品换版跟踪；
- 密评结论的复用周期：非关基系统一般与等保测评周期对齐（三级每年测评一次的口径），关基按条例每年执行。
